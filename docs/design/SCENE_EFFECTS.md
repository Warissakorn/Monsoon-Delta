ส่วนที่มีจริงตอนนี้คือไม้ค้ำ ตราโล่ สัญญาณพรีวิว และข้อความผลค้ำจากรายงานจริง โดยใช้ระบบผลตอบรับและคนทำงานเดิม ดู [คู่มือและภาพค้ำบ้าน](../features/HOUSE_BRACING.md) เพิ่มดินชื้น หยดสองช่องบนแปลงที่เลือก/ชี้ พรีวิว และป้ายข้าวจากความชื้นแล้ว ดู [คู่มือความชื้น](../features/SOIL_MOISTURE.md) รายละเอียดแอนิเมชัน เสียง และจังหวะแสดงผลทั้งหมดในแบบนี้ยังไม่ได้ทำครบ

## ฐานที่มีอยู่และส่วนที่เพิ่ม

ปัจจุบันมีวง/ป้ายคำสั่งประมาณ 1.2 วินาที, ป้ายผลเทิร์นสูงสุด 12 จุด, ลูกศรกระแสน้ำสูงสุด 48 ขอบ, ริ้วผิวน้ำ, ฝน, แสงตามฤดู, คนเดินทำงาน และภาพอาคารตามอายุแล้ว ดู [ผลตอบรับ](../features/ACTION_FEEDBACK.md), [หมู่บ้านมีชีวิต](../features/LIVING_VILLAGE.md) และ [ภาพเดิม](../features/VISUAL_REFRESH.md)

ชุดนี้เสนอรายละเอียดและการประสานเอฟเฟกต์เพิ่ม ไม่เรียกฝน ถนน หรือคนเดินว่าเป็นระบบใหม่:

| กลุ่ม | สิ่งที่เพิ่ม |
|---|---|
| กลไกใหม่ | ภาพค้ำบ้าน/หมดอายุ ดินเก็บความชื้น เศษติดประตู และการเก็บกวาด |
| อ่านอันตราย | แถบระดับน้ำเทียบความทนของอาคาร แยกผลจริงจากค่าคาดการณ์ |
| ผลจากการลงมือ | ละอองดิน/เศษไม้ตามคำสั่งที่สำเร็จ รอยเสียหายที่ตรงรายงาน และภาพแยกผลข้าวกับอาหารปลา |
| จังหวะฤดู | รายละเอียดริมฝั่งและพืชตอบฤดู ช่วงเก็บเกี่ยวที่อ่านผลก่อนฉลอง |

ไม่มีเอฟเฟกต์เปลี่ยนแรงงาน อาหาร ไม้ น้ำ ความทน หรือ RNG ของเกม ภาพค้ำบ้านเพิ่มได้ก็ต่อเมื่อกติกาค้ำบ้านเปิดใช้จริง; การตกแต่งบ้านจากระบบอายุเดิมไม่แปลว่าความทนน้ำเพิ่ม

## ภาษาภาพสามสถานะ

| สถานะ | รูปร่าง/ข้อความ | การเคลื่อนไหว |
|---|---|---|
| **กำลังวางแผน** | เส้นประสีทอง ขอบโปร่ง และคำว่า “คาดการณ์เทิร์นนี้” | นิ่ง ไม่มีของกระเด็น ไม่มีป้ายรับอาหาร ไม่มีท่าฉลอง |
| **ผลจริงที่เพิ่งเกิด** | เส้นทึบสีอ่อน ป้ายผลจริง และตัวเลขจากรายงานที่ commit แล้ว | เคลื่อนไหวสั้นตามเหตุ เช่น น้ำไหล → บ้านรับน้ำ → แสดงผล |
| **สภาพที่ยังคงอยู่** | รูปทรงคงที่ เช่น ไม้ค้ำ ดินชื้น หรือเศษกิ่งไม้ พร้อมสัญลักษณ์อ่านค่า | ไม่วนแอนิเมชันเตือนตลอดเวลา; เคลื่อนไหวละเอียดได้เฉพาะของตกแต่ง |

เหตุการณ์ผิดกฎใช้ป้ายเหตุผลเดิม ไม่เปิดเอฟเฟกต์สำเร็จ ผู้เล่นปิดพรีวิวแล้วต้องยังเห็นสถานะจริงและคำเตือนสำคัญในแผงคำแนะนำ ระหว่างเล่นผลจริงให้พักภาพคาดการณ์ของเทิร์นถัดไปตามระบบเดิม เพื่อไม่วางระดับน้ำสองเหตุการณ์ทับกัน

รูปทรงต้องช่วยแยกความหมาย: โล่มีเลข = ความทนชั่วคราว, หยดน้ำสองช่อง = ความชื้น, กิ่งไม้พร้อมขีด = การอุดตัน, สามเหลี่ยม/รอยแตก = เสี่ยงเสียหาย สีเป็นข้อมูลเสริม ไม่ใช้แดง–เขียวอย่างเดียว

ghost ของคำสั่งก่อนคลิกใน FX02/FX06 เป็นความสามารถที่เสนอเพิ่ม ไม่ใช่ API ปัจจุบัน: ต้องสำเนา state → validate/apply คำสั่งบนสำเนา → preview สำเนานั้น โดยไม่ผ่าน GameSession/checkpoint และไม่เปลี่ยน state/RNG ต้นฉบับ คำสั่งที่ผิดกฎแสดงเหตุผลแทนผลน้ำ หากยังไม่มี helper นี้ ให้แสดงเพียงเงาตำแหน่ง/ต้นทุนก่อนคลิก แล้วใช้พรีวิวเดิมหลังคำสั่งสำเร็จ

## เอฟเฟกต์ 12 รายการ

`P0` = ภัยที่อาจจบรอบ, `P1` = ความเสียหาย/กลไกที่ต้องตอบสนอง, `P2` = ผลจากคำสั่ง/ผลผลิต, `P3` = บรรยากาศ เมื่อพื้นที่หรือจำนวนเอฟเฟกต์เต็ม ให้ P0/P1 มาก่อนเสมอ

### FX01 — น้ำถึงฝั่ง / Shore contact

- **ต่อยอดของเดิม:** ใช้กระแสจริงจาก `TurnReport.flow_edges` ร่วมกับช่องที่มีผิวน้ำ ไม่สุ่มสร้างทิศใหม่; จุดกระทบเลือกจากการส่งน้ำที่บันทึกไว้และรูปฝั่ง ใช้ขอบเด่นชุดเดียวกับ FlowView
- **ภาพ:** ริ้วน้ำสั้นจบด้วยฟองรูปโค้งที่ชายฝั่ง 0.35–0.65 วินาที ฟองไม่วิ่งทะลุอาคารหรือขึ้นพื้นที่แห้ง และไม่แสดงว่าเกิดการกัดเซาะ เพราะยังไม่มีกฎนั้น
- **พรีวิว/สถานะ:** พรีวิวคงลูกศรเส้นประเดิม ไม่แสดงคลื่นกระแทก; น้ำนิ่งไม่มีคลื่นทิศปลอม ผลจริงหมดแล้วเหลือผิวน้ำตาม state
- **Reduce motion / ลำดับ:** เปลี่ยนเป็นขีดฟองคงที่อายุ 0.6 วินาทีหรือซ่อนได้; P3 และถูกตัดออกก่อนข้อมูลอื่น

### FX02 — ค้ำบ้านพร้อมรับน้ำ / House bracing

- **กลไกใหม่:** เริ่มหลัง `brace_house` สำเร็จและ `brace_turns = 1` เท่านั้น; ใช้ได้กับบ้านธรรมดา/บ้านยกพื้นตามกฎ ไม่ใช้กับศาลา
- **ภาพ:** ไม้ค้ำสองด้านประกอบขึ้นใน 0.25 วินาที มีฝุ่นสั้นเฉพาะฐาน ต่อด้วยโล่เส้นทึบ “1 เทิร์น” คงอยู่จน resolve หรือ Undo ไม่ครอบบ้านด้วยฟองพลังงานทึบ
- **พรีวิว/สถานะ:** hover คำสั่งใช้ไม้ค้ำเส้นประ พร้อมต้นทุนจริง; หลังสั่งสำเร็จใช้รูปทึบ แถบความทนแสดงค่าใหม่ แต่ผิวน้ำและความสูงพื้นที่ไม่ลดลง
- **Reduce motion / ลำดับ:** แสดงไม้ค้ำทันทีโดยไม่มีฝุ่น; P2 ตอนก่อสร้าง และ P1 สำหรับสถานะที่ยังรอเทิร์น

### FX03 — ค้ำรับแรงและหมดอายุ / Brace resolution

- **กลไกใหม่:** อ่าน `brace_results` ที่เสนอในเอกสารกลไก แล้วจัดชื่อสำหรับภาพเอง: `held` เมื่อ `prevented_loss` จริง, `unused` เมื่อ `level < base_threshold`, `overwhelmed` เมื่อ `level >= protected_threshold`; ทั้งสามเป็นหมวดภาพที่ derive จากรายงาน ไม่เพิ่ม outcome ของเกมอีกชุดและไม่เดาจากภาพ
- **ภาพ:** `held` ให้ไม้ค้ำโยกเล็กน้อยครั้งเดียว 0.2 วินาทีและป้าย “ค้ำไว้ได้”; `unused` จางโล่พร้อม “หมดระยะค้ำ”; `overwhelmed` ใช้ FX10 และไม่แสดงคำว่าป้องกันสำเร็จ
- **พรีวิว/สถานะ:** พรีวิวแสดงผลที่คาดแบบนิ่ง มีคำว่า “คาดการณ์”; ทุกกรณีไม้ค้ำหายหลังเทิร์นนี้ตาม state โดยแอนิเมชันหมดอายุไม่เป็นผู้ล้างค่า
- **Reduce motion / ลำดับ:** คงไม้ค้ำระหว่างอ่านผล แล้วเปลี่ยนเป็นสภาพสุดท้ายทันที; P1 ห้ามป้ายหมดอายุบังการแจ้งบ้านพัง

### FX04 — ดินเก็บฝน / Retained moisture

ส่วนที่มีจริง: สีดินตามค่าปัจจุบัน หยด 0–2 บนแปลงที่เลือก/ชี้และค่าพรีวิวแยก ป้ายข้าวสะสมจากรายงาน และข้อมูล inspector/ประวัติ มี Reduce motion แบบคงสถานะ ส่วน transition 0.3 วินาทีและเสียงด้านล่างยังเป็นแบบเสนอ ไม่ใช่ผลวัดของ runtime

- **กลไกใหม่:** อ่าน `soil_moisture` 0–2 ของนาที่เปิดกติกาใหม่; ใช้ `moisture_changes` ซึ่งมีพิกัด `before`, `after` และ `yield_from_moisture` ตามเอกสารกลไก
- **ภาพ:** ดินระดับ 2 มีร่องสีน้ำตาลเข้ม, ระดับ 1 เหลือแนวชื้นบาง, ระดับ 0 เป็นสีดินปกติ; ข้างแปลงมีหยดน้ำสองช่อง เมื่อความชื้นถูกใช้ เปลี่ยนหนึ่งช่องใน 0.3 วินาที
- **พรีวิว/สถานะ:** ghost แสดงหยดน้ำที่จะเหลือ แต่ไม่เปลี่ยนดินจริง; ผลผลิตจากความชื้นใช้ป้าย “ข้าวสะสม +1” ไม่ใช่ “อาหาร +1” และไม่เล่นซ้ำเมื่อบึงเป็นแหล่งผลิตของเทิร์นนั้น
- **Reduce motion / ลำดับ:** เปลี่ยนสีดินและสัญลักษณ์ทันที ป้ายอยู่นิ่ง; P2 ป้ายหยดน้ำแสดงเมื่อเลือกช่องหรือเปิดชั้นข้อมูลดิน เพื่อไม่ให้ทั้งกระดานรก

### FX05 — เศษวัสดุสะสมที่ประตู / Gate debris

- **กลไกใหม่:** อ่าน `gate_debris` 0–2 และ `gate_debris_changes` จากน้ำไหลเข้าจริงในฤดูฝน; ใช้ `conductance_used` เทียบ `conductance_next` เพื่อสื่อว่าการสะสมมีผลกับการไหล **เทิร์นถัดไป** ไม่ลดกระแสในภาพผลเทิร์นที่เพิ่งคำนวณย้อนหลัง
- **ภาพ:** ระดับ 1 เป็นกิ่งไม้สองสามชิ้น ระดับ 2 เป็นกลุ่มกิ่งไม้หนาขึ้นที่ฐานประตู พร้อมขีด 1/2; เพิ่มกิ่งไม้ช่วงท้ายผลจริงใน 0.35 วินาที
- **พรีวิว/สถานะ:** แยก “สิ่งกีดขวางตอนนี้” กับ “หลังจบเทิร์นนี้จะเพิ่ม”; เมื่อเพิ่มขึ้นแสดงป้าย “มีผลต่อการไหลเทิร์นหน้า” ไม่ใช้เศษลอยจำนวนมากเพื่อสื่อปริมาณที่ solver ไม่ได้จำลอง
- **Reduce motion / ลำดับ:** เปลี่ยน mesh และขีดระดับทันที; P1 แสดงสถานะได้แม้ประตูปิด ไม่วาดลูกศรไหลผ่านประตูที่ปิด

### FX06 — เก็บกวาดประตู / Clear the gate

- **กลไกใหม่:** เริ่มหลัง `clear_gate` สำเร็จเท่านั้น ต้นทุนและค่าที่ล้างมาจากผลคำสั่ง ไม่ใช้การเดินถึงของคนงานเป็นเงื่อนไขล้าง
- **ภาพ:** เศษกิ่งไม้ยกเข้ากองข้างฝั่งแล้วหายใน 0.4 วินาที ป้ายแรงงานใช้ช่องตอบรับเดิม; หากมีทางเดินที่ถูกต้อง ค่อยส่งคนทำงานด้วยคิวเดิม
- **พรีวิว/สถานะ:** ถ้าคำสั่งยังไม่ได้ใช้ แสดงประตูสะอาดแบบเส้นประและผลน้ำคาดการณ์; หลังใช้ให้ refresh พรีวิวทันที ไม่เปิดภาพน้ำพุ่งจริงก่อนจบเทิร์น
- **Reduce motion / ลำดับ:** แทนด้วยประตูสะอาดและป้ายคงที่ทันที; P2 การเก็บกวาดไม่คืนไม้หรืออาหาร

### FX07 — ขีดระดับน้ำกับความทน / Waterline warning

- **ต่อยอดคำเตือนเดิม:** อ่านระดับน้ำจาก state/preview resolver และค่าทำลายจริงของอาคาร ไม่ใช้ความเข้มฝนหรืออายุบ้านทำนายความเสียหาย สำหรับเทิร์นที่มีค้ำ ใช้ `protected_threshold` จาก `brace_results` ของผลนั้น เพราะ state หลัง preview/resolve ล้างค้ำแล้วและไม่บอกค่าที่ใช้รับน้ำเทิร์นนี้
- **ภาพ:** ช่องที่เลือกหรือเสี่ยงสูงมีมาตรระดับ 0–3 ข้างฐาน; เส้นทึบคือระดับจริง เส้นประคือระดับหลังจบเทิร์น และขีดรอยแตกคือค่าทำลาย ระบุ “ศาลาเสี่ยงแพ้” แยกจากบ้านพัง
- **พรีวิว/สถานะ:** ไม่มีไฟแดงกะพริบวน; ความเสี่ยงใช้ขอบคงที่และปุ่มดูรายละเอียด โดยไม่ย้ายกล้องเองทุกครั้งที่พรีวิวเปลี่ยน
- **Reduce motion / ลำดับ:** รูปคงที่เหมือนโหมดปกติ; ศาลา P0 อาคารอื่น P1 ใช้ inspector แสดงตัวเลขครบเมื่อมาตรเล็กเกินอ่านที่มุมซูมไกล

### FX08 — ข้าวอยู่ในนา ปลาเข้าคลัง / Production receipts

- **ต่อยอดผลผลิตเดิม:** `paddy_gains` แสดงการเพิ่มผลข้าวสะสม; `fish_food_by_tile` แสดงอาหารปลาที่ได้จริง; ข้าวเข้าคลังใช้ผลเก็บเกี่ยวจาก session ไม่ใช้จำนวนคนเดินหรือตะกร้า
- **ภาพ:** ข้าวใช้เมล็ดสีอุ่นรวมเหนือแปลง 0.45 วินาทีแล้วคงแถบผลสะสม; ปลาใช้ไอคอนปลาและ “อาหาร +N” 0.6 วินาที ช่วงเก็บเกี่ยวค่อยใช้ไอคอนข้าวกับจำนวนอาหารจริง
- **พรีวิว/สถานะ:** พรีวิวใช้ป้ายเส้นประ “คาดว่าจะได้”; แสดง source “บึง” หรือ “ดินชื้น” ใน inspector สำหรับกฎใหม่ โดยนาหนึ่งช่องมีป้ายผลผลิตสูงสุดหนึ่งป้ายต่อเทิร์น
- **Reduce motion / ลำดับ:** ป้ายคงที่ ไม่มีไอคอนบินเข้าคลัง; P2 รวมหลายช่องเป็นยอดย่อเมื่อเกินเพดาน และให้รายการเต็มอยู่ในสรุป

### FX09 — ร่องรอยของงาน / Work traces

- **ต่อยอดคำสั่งและคนงานเดิม:** ใช้คำสั่งสำเร็จพร้อม delta; ขุด/ถมเป็นเศษดิน, ตัดเป็นเศษไม้, ปลูกเป็นดินยุบเบา ๆ และสร้างเป็นชิ้นส่วนประกอบ ห้ามแสดงตอน command validator ปฏิเสธ
- **ภาพ:** รายละเอียดเฉพาะจุด 0.2–0.45 วินาที อยู่ต่ำกว่าตัวอาคารและป้ายต้นทุน หลีกเลี่ยงฝุ่นก้อนใหญ่บังกระดาน; คนงานไม่จำเป็นต้องไปถึงก่อนแสดงผล
- **พรีวิว/สถานะ:** แผนสร้างใช้เงารูปทรงนิ่ง; งานรื้อแสดงของหายตาม state แต่ไม่สร้างรางวัลจากเศษไม้ที่เห็น การคืนไม้ยึด delta ของคำสั่ง
- **Reduce motion / ลำดับ:** ใช้วงตอบรับและ delta เดิม ไม่มีเศษวัสดุกระเด็น; P2 และสามารถปิดรายละเอียดนี้ทั้งหมดได้โดยไม่เสียข้อมูล

### FX10 — ผลเสียหายที่อ่านทัน / Damage aftermath

- **ต่อยอดความเสียหายเดิม:** ใช้ `destroyed`, `paddies_died` และ outcome จริงเท่านั้น บ้านพังในกฎเดิมทันที ไม่แสดงรอยร้าวสะสมราวกับมี HP หรือซ่อมบ้านคืนได้
- **ภาพ:** หลังคายุบสั้น 0.3 วินาทีแล้วเหลือรอยฐานชั่วคราว 0.8 วินาที; นาตายเปลี่ยนเป็นแปลงล้มสีหม่น ภาพเศษซากไม่รับคลิกและไม่บังช่องที่ state ว่างแล้ว
- **พรีวิว/สถานะ:** พรีวิวใช้โครงร้าวนิ่ง ไม่เล่นการถล่ม; ถ้ารอบจบให้เปิดสรุปทันทีและใช้ภาพนิ่งประกอบ ไม่หน่วงหน้าจอแพ้เพื่อรอเอฟเฟกต์ครบ
- **Reduce motion / ลำดับ:** เปลี่ยนสภาพทันทีพร้อมป้ายเหตุ; P0 เมื่อจบรอบ มิฉะนั้น P1 ไม่มีจอสั่นหรือ flash เต็มจอ

### FX11 — ริมน้ำเปลี่ยนฤดู / Seasonal margins

- **ต่อยอดฤดูเดิม:** ใช้ฤดูปัจจุบันและช่องเปียกจริง เพิ่มกอหญ้าริมฝั่งไหวเบา ๆ และประกายฝนบนพื้นที่เปียก ไม่เอาความหนาฝนมาบอกค่าฝนอนาคตที่ยังไม่เปิดเผย
- **ภาพ:** เปลี่ยนสีรายละเอียดตามแสงฤดูภายใน 1.0–1.4 วินาทีพร้อม tween เดิม ไม่เพิ่มวงจรกลางวัน/กลางคืนที่ผู้เล่นอาจเข้าใจว่าเป็นเวลาเล่น
- **พรีวิว/สถานะ:** บรรยากาศอยู่บน state ปัจจุบัน พรีวิวไม่เปลี่ยนฤดูทั้งฉาก; รายละเอียดนี้ไม่มีผลซับน้ำ ชนิดพืช หรือทางเดิน
- **Reduce motion / ลำดับ:** หยุดพืชและประกาย ซ่อนฝน เปลี่ยนสีทันทีตามพฤติกรรมเดิม; P3

### FX12 — หมู่บ้านตอบรับเก็บเกี่ยว / Harvest response

- **ต่อยอดภาพคนและสภาพหมู่บ้าน:** ใช้รายงานเก็บเกี่ยวหลังคิดคนย้าย อาหารเน่า และ outcome ครบแล้ว เลือกท่าตอบรับจากผลจริง ไม่ใช่จำนวนข้าวก่อนกิน
- **ภาพ:** ถ้ารอดและไม่มีคนย้าย แสดงคน 2–3 คนยกมือ/ยกตะกร้าสั้น 0.6 วินาที; ถ้ามีคนย้ายใช้ท่าหยุดงานนิ่งและสรุปเหตุ ไม่มีพลุหรือฉลองทับการสูญเสีย
- **พรีวิว/สถานะ:** พรีวิวมีเพียงตัวเลข; ท่าตอบรับไม่เพิ่มประชากรและไม่บังคับเกิดตัวละครเท่าจำนวนคนที่ย้ายจริง โหลดเกมที่หน้าเก็บเกี่ยวไม่เล่นรับรางวัลซ้ำ
- **Reduce motion / ลำดับ:** ใช้ภาพท่าคงที่และข้อความสรุป; P2 เมื่ออ่านผลสำคัญแล้ว และลดเป็น P3 หากต้องแย่งพื้นที่กับคำเตือน

## ลำดับภาพหนึ่งเทิร์น

ตัวอย่างนี้เป็น storyboard ที่เสนอ ไม่ใช่เวลาที่ resolver ใช้คำนวณ ปัจจุบัน FlowView แสดงผลจริงได้ 2.6 วินาที; แบบ 1.6 วินาทีด้านล่างต้องเปลี่ยนเป็นนาฬิกากลางร่วมกับ FlowView/ป้ายผล ก่อนเปิดใช้ ห้ามคืนพรีวิวที่ 1.6 วินาทีขณะที่กระแสจริงเดิมยังเล่นอยู่ หากยังไม่ปรับนาฬิกากลาง ให้ยึดจังหวะสิ้นสุดผลจริงเดิม:

| เวลาแสดงผล | สิ่งที่เห็น | ข้อมูลที่ยืนยันแล้ว |
|---|---|---|
| ก่อนกดจบ | บ้านมีค้ำทึบ 1 เทิร์น; ประตูมีเศษระดับเดิม; น้ำคาดการณ์เป็นเส้นประ | state ของคำสั่งปัจจุบัน และ preview บนสำเนา |
| 0.00 วินาที | commit เทิร์นและ checkpoint ตาม session; ปิดชั้น ghost ของเทิร์นถัดไปชั่วคราว | ผลเทิร์นทั้งหมดเสร็จแล้ว ไม่มีการจ่ายทรัพยากรตามเวลาแอนิเมชัน |
| 0.00–0.45 | ริ้วตามขอบน้ำจริงและฟองริมฝั่ง | รายงานการส่งน้ำจริง |
| 0.25–0.75 | บ้านค้ำรับน้ำหรือความเสียหาย พร้อมมาตรระดับ | ขั้น damage และ outcome จริง; ภัยแพ้แทรกได้ทันที |
| 0.55–1.20 | ผลข้าว/ปลา ดินชื้นที่เปลี่ยน และกิ่งไม้เพิ่มที่ประตู | ผลผลิตจริงและสถานะสะสมสำหรับเทิร์นหน้า |
| 1.20–1.60 | ป้ายสั้นจาง คืนพรีวิวปัจจุบัน; ข้อมูลสำคัญคงใน inspector/ประวัติ | state ปัจจุบัน ไม่รัน resolver อีกครั้งเพื่อทำภาพ |

ช่วงเวลา overlap ได้และข้ามได้ การกดคำสั่งใหม่หรือสลับพรีวิวทำให้จบภาพผลเก่าทันทีแล้ว render จาก state ล่าสุด ผู้เล่นไม่ต้องรอคนเดิน ฝุ่น หรือคลื่นหมดก่อนวางแผนต่อ ช่วงเก็บเกี่ยว/จบรอบให้ modal และสรุปมีสิทธิ์เหนือ timeline นี้

## สัญญาข้อมูลและวงจรชีวิต

- `core/` ตัดสินกฎและบันทึกข้อมูลผลครบก่อนส่งให้ภาพ; `view/`/`ui/` อ่านข้อมูลอย่างเดียว รายการ visual event ที่เสนอมี `event_id`, `state_revision`, `mode`, พิกัด, ชนิด, ค่าก่อน/หลัง และเหตุ ไม่มี callback ที่มอบผลผลิตหรือเปลี่ยนความทน
- ข้อมูลเดิมอ่านจาก [TurnReport](../../core/turn_report.gd), [FlowView](../../view/flow_view.gd), [ActionFeedback](../../view/action_feedback.gd), [DeltaAtmosphere](../../view/delta_atmosphere.gd) และ [VillageLifeView](../../view/village_life_view.gd); `brace_results` และ `moisture_changes` มีในรายงาน runtime แล้วสำหรับกฎที่เปิดใช้ ส่วน `gate_debris_changes` ยังเป็นข้อมูลเสนอที่ต้องพัฒนาพร้อมกลไกประตู
- ค่า debris ใช้ผล float64 จาก core ตามแบบกลไก ไม่คำนวณสถานะเกมย้อนจาก `flow_edges` สำหรับภาพซึ่งลดความละเอียดได้ การลดคุณภาพหรือปิดภาพต้องไม่เปลี่ยนการอุดตัน
- Undo/Redo, retry, load และเปลี่ยนรอบทำให้ revision เก่าสิ้นสุด: ยกเลิก tween/particle/งานคนของ event เก่า แล้วสร้างเฉพาะภาพสถานะใหม่ ไม่เล่นใบเสร็จหรือฉลองย้อนหลัง
- การโหลดคืนไม้ค้ำ ดินชื้น และกิ่งไม้จาก state ได้โดยตรง แต่ไม่มี emitter/เวลาคงเหลือ/คิวเอฟเฟกต์ลงเซฟ การเปลี่ยนภาษาอัปเดตข้อความเดิม ไม่ส่ง event รับผลใหม่
- Pause หยุดอายุเอฟเฟกต์ กระแสและงานคน; กลับมาเล่นต่อจากเวลาเดิม ไม่สร้าง burst สะสมระหว่างหยุด สรุปผล/เมนู modal ต้องกั้น Space/Enter และไม่ปล่อย input ไปจบเทิร์น
- พรีวิวสร้าง event คนละ namespace กับผลจริงและห้ามเขียน progress/RNG/เซฟ; ตำแหน่งรายละเอียดตกแต่งใช้พิกัด/ID คงที่หรือ RNG สำหรับภาพที่แยกจาก RNG เกม
- เปิด Reduce motion ระหว่างเล่นต้องลบการเคลื่อนไหวทันทีโดยรักษาสัญลักษณ์/ตัวเลข; ปิดกลับไม่เริ่มผลผลิตที่จบไปแล้ว ความเร็วเครื่องและ frame rate ไม่เปลี่ยนค่ารายงาน

## งบภาพและการอ่านฉาก

ใช้ Compatibility renderer เดิมเป็นฐาน ไม่ตั้งเงื่อนไขว่าต้องมี volumetric fog, screen-space reflection หรือระบบ particle ที่ผูก compute ใหม่ รูปทรงไม้ค้ำ กิ่งไม้ และฟองใช้ mesh/material ร่วมกันและรวมชุดวาดเมื่อเหมาะสม; ไม่สร้างไฟและเงาแยกให้แต่ละเอฟเฟกต์

| งบที่เสนอ | เพดานเริ่มทดลองรวมทั้งของเดิมและของใหม่ |
|---|---|
| ป้ายข้อความลอย | คง 12 จุดร่วมกับ ActionFeedback ไม่เพิ่มเป็น 12 จุดต่อระบบ; พิกัดเดียวรวม delta และไม่ให้ป้ายผลผลิตทับความเสียหาย |
| น้ำตามขอบ | คงขอบเด่น 48 ขอบร่วมกับ FlowView; ฟองเลือกได้สูงสุด 8 จุดจากชุดนั้น |
| รายละเอียด burst | สูงสุด 6 จุดพร้อมกัน จุดละไม่เกิน 6 ชิ้น อายุไม่เกิน 0.65 วินาที; ใช้ pool หรือ batch และทิ้ง P3 เก่าก่อน |
| คนทำงาน | ใช้ตัวแทนเดิมไม่เกิน 12 คนและคิว 24 งาน; เก็บกวาด/ค้ำ/ฉลองแชร์เพดาน ไม่สร้างชุดคนเพิ่มอีกระบบ |
| ภาพสถานะถาวร | ไม่เกิน 1 กลุ่ม mesh ต่อช่องต่อชนิด; ข้อมูลละเอียดโชว์เฉพาะเลือกช่องหรือเปิดชั้นข้อมูล |
| ความโปร่งใส | จำกัดฟอง/ฝุ่นให้ซ้อนเหนือผิวน้ำไม่เกิน 1 ชั้นตกแต่งต่อช่อง; ป้ายข้อมูลสำคัญแยกจากงบตกแต่ง |

หมดงบแล้วตัดรายละเอียดได้ แต่ผลจริงยังอยู่ในประวัติและคำเตือนระดับสูงยังอยู่ในแผงคำแนะนำ ไอคอนใช้สัญลักษณ์กับข้อความรองรับไทย/อังกฤษ มีพื้นหลังช่วยอ่านไม่ว่าฤดูใด; อย่าลดขนาดตัวอักษรเพื่อใส่ป้ายเพิ่ม

เพดานเหล่านี้เป็นเป้าการผลิต ไม่ใช่คำอ้างว่าเพิ่ม draw calls เท่าไรหรือได้กี่ FPS ต้องวัด native 1280×720 ทั้งไทย/อังกฤษบนเครื่องเดิม โดยเทียบฉากเดียวกัน เปิด/ปิดชุดใหม่ และแยกค่า software renderer จากฮาร์ดแวร์จริง

## ลำดับพัฒนาและเกณฑ์รับงาน

เริ่ม FX07/08/09 เพื่อทำให้กฎเดิมอ่านง่ายขึ้น จากนั้นทำ FX02/03 พร้อมค้ำบ้าน, FX04 พร้อมความชื้น, FX05/06 พร้อมประตูอุดตัน แล้วเพิ่ม FX01/10/11/12 ตามงบภาพ แต่ละรายการเปิดได้ต่อเมื่อข้อมูลที่อ้างถึงมีจริงและผ่านการตรวจ

ก่อนส่งแต่ละชุดต้องตรวจ: preview ไม่เล่นผลจริง, ป้ายตรงรายงาน, Undo/Redo ยกเลิกภาพเก่า, pause/skip/load ไม่รับผลซ้ำ, ตั้ง Reduce motion กลาง effect แล้วข้อมูลยังครบ, แป้นพิมพ์/เมาส์ไม่รอแอนิเมชัน และภาพไม่เปลี่ยน bytes ของ state/RNG/checkpoint จากการปล่อยเวลา

ตรวจภาพอย่างน้อยฉากน้ำนิ่ง/ฝนมาก, บ้านค้ำที่รอดและยังพัง, ศาลาแพ้, นาใช้บึงเทียบความชื้น, ประตูปิด/เปิด/อุดตัน/เก็บกวาด, เก็บเกี่ยวข้าวมากแต่มีคนย้าย และโหลดหลังผลเกิดแล้ว ภาพหรือ replay แต่ละชุดต้องติดป้าย fixture เมื่อจัด state ไว้

ให้ผู้เล่นลองโดยไม่อธิบายแล้วถาม “ป้ายไหนคือคาดการณ์?”, “อาหารได้แล้วหรือยัง?”, “ประตูนี้จะมีผลกับเทิร์นไหน?” เป้าทดลองคืออ่านถูกอย่างน้อย 2 ใน 3 คนก่อนเพิ่มความซับซ้อน ผลนี้ไม่แทนการตรวจสมดุลกลไกหรืออัตราแพ้ชนะ
