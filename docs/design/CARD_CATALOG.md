# ข้อเสนอการ์ดภูมิปัญญา: 30 ใบที่ทำให้รอบเล่นต่างกัน

สถานะ: **ข้อเสนอสำหรับ M5 ยังไม่ถูกโหลดหรือใช้โดยเกม** ตัวเลขเป็นค่าเริ่มต้นสำหรับทดลอง ไม่ใช่ผลสมดุลที่ยืนยันแล้ว เอกสารนี้คง ID และแนวคิดของการ์ดทั้ง 30 ใบที่มีอยู่ใน [สเปกต้นฉบับ](../specs/07_mods_cards_leaders.md) และขยายเงื่อนไข ผลข้างเคียง และวิธีพิสูจน์ความสนุก จึงไม่ใช่การเพิ่มการ์ดใหม่ 30 ใบเข้าตัวเกม

## กติกากองการ์ด

- ในต้นแบบ M5 ใช้ได้ครบทั้ง 30 ใบตั้งแต่เริ่ม ไม่ต้องปลดล็อกการ์ดที่มีพลังสูงกว่าด้วยการเล่นซ้ำ โปรไฟล์ปลดล็อกแผนที่และความท้าทายแยกต่างหาก; ผู้ใหญ่บ้านสี่คนยังเลือกได้ครบเหมือน UI ปัจจุบัน
- ต้นปีทุกปี รวมปีแรก เลือกได้ 1 ใบจาก 3 ใบ หรือ 2 ใบเมื่อข้อจำกัดความยากกำหนด ทุกใบอยู่ถาวรจนจบรอบและถือซ้ำไม่ได้ กดข้ามได้โดยไม่รับทรัพยากรชดเชยและไม่สุ่มใหม่
- ไม่เสนอใบที่มีแล้ว และไม่เสนอใบปลดล็อกที่เปิดใช้อยู่แล้ว โหมด 10 ปีจึงไม่เสนอ `waterwheel` และ `raft_house` เพราะเปิดให้ตั้งแต่เริ่ม
- ประเมินผลถาวรหลังแผนที่ → โหมด → ผู้ใหญ่บ้าน → ความยาก → การ์ดตามลำดับที่เลือก โดยยังไม่รวมผลชั่วคราวรายปี ถ้าผลดีทุกข้อเท่าเดิมหลังปัดเศษและใช้ขอบเขตจริง ให้ตัดใบนั้นออก เช่น `canal_network` และ `clay_soil` ไม่ช่วยหมอดินที่จ่าย 1 อยู่แล้ว ไม่ใช้การไม่มีสิ่งก่อสร้างหรือไม่มีนาในตอนนี้เป็นเหตุคัดออก เพราะผู้เล่นอาจกำลังเปลี่ยนแผน
- ลำดับ ID ก่อนสุ่มต้องคงที่ รายการที่เสนอและการตัดสินใจต้องบันทึกก่อนแสดงหน้าจอ การโหลด พรีวิว Undo และ Redo ไม่สุ่มกองใหม่ หากเหลือไม่ครบจำนวนให้เสนอเท่าที่เหลือ หากไม่เหลือให้ข้ามขั้นนี้โดยไม่เปลี่ยน RNG
- หลังเลือกการ์ด คำนวณ modifier ใหม่ แล้วจ่าย `year_start_food` และ `year_start_wood` ของปีนั้น **ครั้งเดียวก่อนเหตุการณ์** การ์ดรายปีที่เพิ่งเลือกจึงจ่ายทันที ต้องบันทึกขั้นตอนต้นปีและใบเสร็จการจ่ายเพื่อป้องกันรับซ้ำเมื่อโหลด
- การเลือกไม่ใช้แรงงาน ไม้ หรืออาหาร ค่าเสียโอกาสคือไม่ได้เลือกอีกสองใบในปีเดียวกัน หน้าเลือกต้องแสดงผลจริงตามผู้ใหญ่บ้านและความยาก เช่น “ไม้ยุ้งฉาง 3 → 2” แทนข้อความลดราคาที่ไม่บอกฐาน

## 5 แนวเล่น ไม่ใช่ 5 เด็คบังคับ

| แนวเล่น | คำถามที่ผู้เล่นต้องตอบ | สิ่งที่ยังต้องแก้เอง |
|---|---|---|
| ช่างน้ำ | เปลี่ยนเส้นทางให้น้ำหลบหมู่บ้านหรือเข้าพื้นที่ผลิต? | น้ำไหลเร็วและคูที่ลึกขึ้นอาจพาท่วมปลายทาง |
| นาและบึง | เพิ่มนาหรือรักษาผลผลิตต่อแปลง? | ข้าวยังตายได้ ศาลายังต้องอยู่รอด |
| ปลาและเสบียง | เปลี่ยนน้ำท่วมเป็นอาหารหรือเก็บทรัพยากรไว้ก่อน? | ไซใช้พื้นที่และไม้ การมีอาหารไม่สร้างที่อยู่ให้เอง |
| บ้านและชุมชน | รับคนเพิ่มหรือรักษาฐานขนาดเล็ก? | คนมากเพิ่มแรงงาน แต่ต้องกินทุกปี |
| ภูมิปัญญาส่วนรวม | ลงทุนในป่า แรงงาน หรือข้อมูล? | ผลดีต่อระบบน้ำด้านหนึ่งอาจทำให้อีกด้านขาดน้ำ |

`add`, `mul`, `set` คือรูปแบบ modifier ปัจจุบัน ไม่เพิ่มทรัพยากรใหม่หรือ minigame แยก ตารางด้านล่างคือ **ค่าที่เสนอให้ใช้** ส่วนค่าที่ต่างจากต้นฉบับแจกแจงท้ายเอกสาร

## สัญญาที่ implementation ต้องรักษา

1. ใช้ลำดับแผนที่ → โหมด → ผู้ใหญ่บ้าน → ความยาก → การ์ดตามลำดับที่เลือก → `year_mods` ตามระบบปัจจุบัน ค่าเปลี่ยนจากการ์ดต้องไม่เขียนกลับลง `balance.json` และไม่เปลี่ยนสถานะของเกมอื่น
2. ตอนอ่านต้นทุน ปัดด้วย `roundi` แล้วให้ไม้/แรงงานอย่างน้อย 0; ขุดและถมอย่างน้อย 1; รื้ออย่างน้อย 1; `paddy_labor = 0` อนุญาตเฉพาะคำสั่งสร้างนาที่ยังไม่มีนาอยู่ ผู้เล่นกดลงช่องเดิมเพื่อรีเซ็ตผลผลิตหรือข้าวตายไม่ได้ ผลไม้คืนอยู่ระหว่าง 0 ถึงทุนที่ยังบันทึกไว้ ความเน่าจำกัด 0–1 ตอนใช้งาน
3. `fill_amount`/`dig_amount` ไม่ทำให้เกินขอบเขตความสูงเดิม ทุกคำสั่งยังต้องมีเป้าหมายที่ถูกต้อง แม้ราคาจะเป็นศูนย์ ไม่เปลี่ยนขอบเขตน้ำหรือการตัดสินแพ้ของศาลาเพื่อชดเชยการ์ด
4. รอบที่เริ่มใหม่ด้วยกติกา M5 ใช้ซองเซฟ v3 และระบุ ruleset/catalog version เพิ่ม `actual_paid_wood` ต่อสิ่งก่อสร้าง เก็บตอนยืนยันสร้างจากต้นทุนจริง และทำเป็นส่วนหนึ่งของ snapshot/เซฟ/สำเนาพรีวิว คืน `floor(actual_paid_wood × clamp(refund_fraction, 0, 1))` แล้วล้างหลักฐานทุนเมื่อรื้อหรือพัง อาคารจาก mapgen ในรอบ M5 มีทุนคืน 0 ทุนที่ไม่ได้จ่ายไม่สร้างสิทธิ์คืนไม้ การเก็บข้อมูลนี้ใช้กับอาคารใหม่ทุกหลังแม้ยังไม่มีการ์ดเก็บของเก่า เซฟ v1/v2 โหลดด้วย legacy ruleset: คง flow ที่ไม่มีการ์ด/เหตุการณ์และสูตรคืนไม้ตามราคาปัจจุบันเดิม ไม่เดาทุนย้อนหลังและไม่อัปเกรดกติกากลางรอบ
5. ใบที่มี `set` ยังคงเป็นกฎปลดล็อกหรือเกณฑ์เฉพาะตัว ไม่ให้ `set` บนการ์ดหนึ่งลบผลการ์ดอีกใบโดยเงียบ ๆ ชุดนี้ไม่มีการ์ดสองใบที่ `set` ค่าเดียวกัน ก่อนเพิ่มเนื้อหาใหม่ต้องตรวจการชนและแสดงผลจริงเสมอ
6. UI บอกระยะเวลา “จนจบรอบ” กับ “เฉพาะปีนี้” แยกกัน ชื่อและคำอธิบายผูก ID เดิมเพื่อแปลไทย/อังกฤษได้ การ์ดไม่ได้ทำให้พรีวิวสุ่ม และต้องเห็นความเสียหาย/ผลผลิตใหม่ก่อนกดจบเทิร์น

## ตัวอย่างที่ใช้ลองเล่นและตรวจคณิตศาสตร์

| สถานการณ์ | ผลที่ควรเป็น | สิ่งที่ตั้งใจให้ผู้เล่นตัดสินใจ |

| ชาวนา + นารอด 4 แปลง แต่ละแปลงให้ผลฝน 3 ครั้ง | ฐาน `(3+1)×4 = 16`; ข้าวหอมเพิ่ม `2×4` เป็น 24; นาหว่านลด `1×4` เหลือ 20 | พื้นที่ฟรีชดเชยผลผลิตที่เสียต่อแปลงหรือไม่? ไม่คิดอาหารต้นปีเป็นข้าวเก็บเกี่ยว |
| ชาวประมง + ปลาแห้ง + ไซเปียก 2 อัน 3 เทิร์นฝน | `(1+1+1)×2×3 = 18` อาหาร; ถ้าเหตุการณ์ผลปลา×2 เป็น 36 | แผนปลามีรายได้ทันทีและอาจกลบแผนนา ต้องเก็บอัตราชนะของชุดนี้แยก ไม่หั่นตัวเลขส่วนอื่นเพื่อกลบปัญหา |

## ชุดต้นแบบที่แนะนำและเงื่อนไขผ่าน

ให้ทำระบบ data-driven แล้วตรวจครบ 30 ใบ แต่ใช้ชุดลองเล่นที่กำหนด seed และกองเสนอเหมือนกันเพื่อเทียบเหตุและผล: ชาวนา/ข้าวขึ้นน้ำ/ข้าวหอมมะลิ; ชาวประมง/ปลาแห้ง/ปลาร้า; หมอดิน/กระสอบทราย/ลงแขก; ช่างไม้/ครอบครัวใหญ่/หมอตำแย; ป่าทาม/เรือนเพาะชำ/ขอนไม้ ไม่บังคับว่าในเกมจริงต้องสุ่มชุดเหล่านี้ติดกัน

- ตรวจหนึ่งใบต่อครั้งก่อน แล้วจึงตรวจชุดผสมที่ยกตัวอย่าง ค่าอาหาร ไม้ ที่อยู่ และแรงงานต้องตรงสูตร โหลดกลางขั้นต้นปีได้ผลเหมือนเล่นต่อโดยไม่ปิดเกม
- เปิดโหมด 5 และ 10 ปีด้วยผู้ใหญ่บ้านทั้งสี่ ตรวจว่าไม่มีใบปลดล็อกซ้ำหรือใบลดต้นทุนที่ไม่มีผล กองไม่ติดค้างแม้เหลือ 0–2 ใบ ปีละหนึ่งการ์ดหมายถึงสูงสุด 5 หรือ 10 ใบ ไม่ใช่สะสมครบทั้ง 30 ใบในรอบเดียว
- จำลอง seed เดียวกันโดยเลือกการ์ดต่างกัน เก็บอัตราชนะ สาเหตุแพ้ ปีที่แพ้ ผลปลา/ข้าว และการใช้แต่ละคำสั่ง เทียบทั้งผู้เล่นใหม่และผู้เล่นเข้าใจพรีวิว ไม่อ้างว่าเพิ่มตัวเลขอัตราชนะอย่างเดียวเท่ากับสนุกขึ้น
- ทดลองกับคนเล่นให้ตอบได้ว่าการ์ดที่เลือกเปลี่ยนแผนอย่างไร และมีอย่างน้อยสองทางเลือกที่ลังเลจริง ตรวจเฉพาะนาหว่าน ยุ้งฉางใหญ่ และชุดปลาว่าไม่กลายเป็นใบต้องเลือกทุกครั้ง หากทุกคนเลือกใบเดียวเสมอให้แก้ต้นทุน/ผลข้างเคียงแล้วลองใหม่

JSON คู่กันที่ [cards.proposal.json](cards.proposal.json) มีเฉพาะข้อมูลร่างสำหรับตรวจ ID/modifier/จำนวน ห้ามนำไปแทน `data/cards.json` โดยถือว่าได้รับการอนุมัติหรือทดสอบแล้ว
