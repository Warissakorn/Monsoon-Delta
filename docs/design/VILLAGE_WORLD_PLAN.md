# แผนหมู่บ้านลุ่มน้ำ: ภาพและระบบที่ส่งเสริมกัน

แผนที่ผู้ใช้ให้เริ่มพัฒนา 2026-11-07 ต่อจากงานอาคารใน PR #32 ใช้วงจร เตรียมพื้นที่ → จัดคน/วัสดุ → จัดน้ำ → ผลิต/เก็บ → รับฤดู → ซ่อม/พัฒนา

## ลำดับและสถานะ

| ระยะ | งานและเกณฑ์ส่งมอบ | สถานะ |
|---|---|---|
| 1 ข้อมูลและต้นแบบ | ตารางบทบาทพื้นที่/แหล่งข้อมูล จุดวางที่หลบถนนและอาคาร ฉากหมู่บ้านเดียวสำหรับตรวจหลายสภาวะ | ทำในชุดแรก ดู [สัญญาฉาก](../features/VILLAGE_WORLD.md) |
| 2 พื้นที่และชิ้นส่วน | ลานบ้าน รั้ว โอ่ง ราวผ้า ท่าน้ำ เรือ พืช จุดงานและพื้นที่ส่วนกลาง ตำแหน่งคงเดิมหลังโหลด | ทำในชุดแรก |
| 3 สถานะจริง | ระดับน้ำ รอยเปียก/ดินตามฤดู ปริมาณไม้จริง อายุและพัฒนาการเดิม พรีวิวไม่สร้างผลผลิต | ทำในชุดแรก; ไม่เพิ่มประวัติน้ำหลากถาวร |
| 4 กิจกรรมและชีวิต | คนทำงานเดิมร่วมกับสัตว์เล็ก เรือจอด ผ้าและน้ำกระเพื่อมแบบจำกัดจำนวน Pause/Reduce motion และล้างผลผลิตเมื่อโหลด/Undo | ทำในชุดแรก |
| 5 ทดลองขนส่ง | วัตถุดิบหนึ่งชนิด จุดผลิต คลัง ทางบก/ทางน้ำ จุดรับส่ง ความจุ เวลา ของจอง/ระหว่างทาง งานติดขัด พรีวิว/เซฟตรงกับผลจริง | ทำต้นแบบไม้ → โรงเลื่อย → คลัง บนรอบ 365 วันแยกกติกา/เซฟ ดู [คู่มือ](../features/TRANSPORT.md) |
| 6 ทางเลือกและฤดู | บ้านรองรับคน/ทนน้ำ ท่าประมง/ขนของ คลังความจุ/รักษาของ จุดงานกำลังผลิต/แรงงานน้อย และเป้าหมายส่วนกลาง | ยังไม่เปิดใช้; ใช้ผลต้นแบบระยะ 5 กำหนดต้นทุนและข้อแลกเปลี่ยน |
| 7 ตรวจรับ | ตรวจวงจรฉาก ไทย/อังกฤษ เซฟ/Undo/Redo ประสิทธิภาพ และการอ่านสถานการณ์โดยผู้เล่น | มี automated/native QA ของชุดภาพและต้นแบบขนส่ง; human playtest และสมดุลกลไกใหม่ยังค้าง |

ชุดแรกใช้ BoardView 3 มิติของเกมหลัก/รอบยาว/โรงเรียน/ห้องทดลอง รอบ 365 วันยังใช้ YearBoard 2 มิติ การนำภาพเดียวกันไปใช้ต้องมีตัวแปลง YearGame → ข้อมูลฉาก พร้อมตรวจ 127 ช่องก่อนเปิดใช้ ไม่มีการเปลี่ยนกฎรอบค้างหรือเปิดกลไก M5 จากงานภาพนี้

## งานที่ทำแล้วและงานถัดไป

1. ทดสอบว่าผู้เล่นอ่านทางแห้ง ท่าน้ำ และพื้นที่ทำงานได้จากฉาก โดยแยกผลทดลองจากการทดสอบอัตโนมัติ
2. ระยะ 5 ทำแล้วตาม [สัญญาบัญชีและเส้นทาง](../features/TRANSPORT.md): แยกต้นทาง/ของจอง/ระหว่างขน/ปลายทาง และคืนงานเมื่อทางขาด
3. ต้นแบบ 365 วันใช้เซฟ/กติกาแยกแล้ว รักษา float64 งานที่จองราคาเดิม และรางวัลครั้งเดียว การเปลี่ยนกฎที่เข้ากันไม่ได้ครั้งถัดไปต้องกำหนด version ใหม่
4. ตรวจแล้วด้วย automated/native QA: การอนุรักษ์ทรัพยากร พรีวิวเทียบผลจริง Save/Load ระหว่างขน และ Undo/Redo ก่อนขยายสูตรผลิตหรือจำนวนเรือ
5. ทดลองทางเลือกอัปเกรดเพียงสองสายต่อสถานที่ก่อน แล้วจึงปรับสมดุลตามข้อมูลการเล่นจริง

สถานะและคำสั่งตรวจอยู่ใน [คู่มือฉาก](../features/VILLAGE_WORLD.md) / [คู่มือขนส่ง](../features/TRANSPORT.md) ผลตามวันอยู่ใน [ประวัติพัฒนา](../history/PROGRESS.md)
