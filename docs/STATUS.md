ผู้นำใช้ค่าจาก `balance.json`: farmer เพิ่มอาหารข้าวที่ให้ผลผลิต +1 ต่อช่องเมื่อเก็บเกี่ยว; carpenter ลดไม้บ้าน/บ้านยกพื้น/เรือนแพ 1; fisher เพิ่มอาหารไซต่อเทิร์น 1; soil_doctor ลดแรงงานขุด/ถมทั้งสองฤดู 1

เป้าหมายเสริมตรวจหลังเก็บเกี่ยว ต้องผ่านทุกเงื่อนไขในการเก็บเกี่ยว **ครั้งเดียวกัน** แล้วเก็บเหรียญถาวรในรอบนั้น:

| ID | เงื่อนไขพร้อมกัน |
|---|---|
| `none` | ไม่เลือกเป้าหมาย |
| `growth` | ประชากร ≥12 |
| `forest` | ประชากร ≥8 และป่าโตเต็มที่ ≥8 ช่อง |
| `rice` | ประชากร ≥8 และอาหารข้าวในการเก็บเกี่ยวครั้งนั้น ≥18 |

เหรียญให้คะแนนพื้นฐาน 50 เพียงครั้งเดียว การไม่สำเร็จเป้าหมายไม่ทำให้แพ้หรือขัดขวางการชนะ ดูรายละเอียด [รอบยาวและเป้าหมาย](features/LONG_RUNS.md)

## กฎที่ต้องรักษาเมื่อแก้ระบบ

- เทิร์น: จำลองน้ำ → ซับน้ำ → ระเหยเฉพาะฤดูแล้ง → ความเสียหาย → ผลผลิต; ศาลาถึงระดับน้ำ 2 แพ้ทันทีตามค่าเริ่มต้น
- เก็บเกี่ยว: รวมข้าว → กินอาหาร → คนย้ายเพราะหิว → คนย้ายเพราะบ้านไม่พอ → เกิด → อาหารเน่า → ตรวจผลรอบ/เป้าหมาย คนเหลือ 0 แพ้; รอดเก็บเกี่ยวปีสุดท้ายชนะ
- พรีวิวเทิร์นปัจจุบันใช้ resolver เดียวกับผลจริงบนสำเนา ต้องไม่เปลี่ยน state/RNG/ประวัติ/เซฟ; ไม่ใช่คำรับประกันฝนที่ยังไม่เปิดเผยของเทิร์นอนาคต
- คำสั่งและ resolve ไม่สุ่มเพิ่ม; forecast สุ่ม 4 draws ต่อปี เก็บ RNG ไว้กับ state
- Undo/Redo ใช้ snapshot เต็ม สูงสุด stack ละ 200; คำสั่งใหม่ล้าง Redo; จบเทิร์นล้างทั้งคู่; สำเนา/โหลดไม่มีประวัติเหล่านี้
- คะแนน = `(ประชากร×10 + อาหาร + โบนัส) × (1 + difficulty×0.1)` ปัดเป็นจำนวนเต็ม; เมื่อชนะได้เพิ่มบ้านไม่พัง 50 / ศาลาไม่เคยเปียก 30; เหรียญเป้าหมายเพิ่มก่อนตัวคูณ
- Modifier จริงเรียง default → map → run mode → leader → difficulty สะสม → year mods; ยังไม่รวมการ์ด

## เซฟและขอบเขตข้อมูล

- `GameSession` เป็นผู้ checkpoint หลังเปลี่ยนรอบจริง; `GameFlow` ไม่ทำ disk I/O
- เกมใหม่จากเมนู/boot มีประวัติภาพอาคาร ใช้ envelope **v3** เมื่อเล่นกฎเดิม หรือ **v4** เมื่อเปิดค้ำบ้านอย่างเดียว และ **v5** เมื่อเปิดความชื้นในนา (เดี่ยวหรือร่วมค้ำบ้าน); รอบ legacy ที่ไม่มีประวัติภาพยังใช้ **v1** สำหรับ classic + none และ **v2** สำหรับ long หรือมีเป้าหมาย; internal state version ยังเป็น 1 ทุกแบบ
- `bracing_v1` เก็บ ruleset และสถานะค้ำครบทุกช่องใน v4 ค้ำหมดหลัง resolve จริงแม้แห้งหรือช่วยไม่สำเร็จ สำเนา/พรีวิว/Undo/Redo รักษาสถานะครบ ไม่เพิ่มค้ำให้เซฟเก่า รุ่นเซฟหรือ ruleset อนาคตที่ไม่รองรับแจ้ง error และรักษาไฟล์ไว้
- v5 ต้องมี `soil_moisture` 0–2 ครบทุกช่อง โดยช่องที่ไม่ใช่นาหรือนาตายเป็น 0; combined ruleset เก็บค้ำด้วย ไม่เติมความชื้นให้เซฟ v1–v4 รายงาน `moisture_changes` อยู่เฉพาะ session ไม่ลงเซฟ
- `settlement_progress` มีสภาพส่วนรวม/ประวัติอาคาร ตรวจหลังเก็บเกี่ยวและพัฒนาภาพทีละระดับ ไม่เพิ่มทรัพยากร ความจุบ้านหรือความทนน้ำ โหลด v1/v2 ไม่สร้างอายุย้อนหลังหรือเขียนไฟล์ใหม่เอง
- เซฟรักษา float64/RNG แบบตรงค่า; validator ปฏิเสธฟิลด์การ์ด/ข้อเสนอ/เหตุการณ์ที่ไม่ว่าง เพราะยังไม่มีระบบรองรับ
- ประวัติผลเทิร์นเก็บเฉพาะ session สูงสุด 30/60 รายการ; โหลดเริ่มประวัติใหม่; Undo/Redo ไม่ลงเซฟ
- โรงเรียนสายน้ำใช้ tutorial state ในหน่วยความจำ ไม่เขียน checkpoint หรือสมุดตรา; ออกจากบทเริ่มใหม่และ Continue ปกติคงเดิม ผลผ่านบทแยกจาก Outcome.WIN ของรอบ 5 ปี
- ภาษา/Reduce motion/คำเตือนแรงงานอยู่ใน settings แยกจาก checkpoint รอบเล่น ดู [สัญญาเซฟ](development/SAVE_IO.md)
- เส้นทาง คนเดิน กระแสน้ำรายขอบ และแผนที่อาหารข้าว/ปลาสำหรับภาพเป็นข้อมูลชั่วคราว ไม่ลงเซฟและไม่สุ่มเพิ่ม ถนนไม่เปลี่ยนสิทธิ์การผลิตของรอบเดิม

## ยังไม่มีในเกม

**M5 ยังเป็นแบบเสนอที่รออนุมัติ**: การเลือกการ์ด เหตุการณ์ ข้อตกลงรายปี profile/unlocks แผนที่ valley/estuary และ daily challenge ไม่มี flow เล่นจริง แม้ enum/fields/modifier บางส่วนเตรียมไว้แล้ว `is_daily` ยังเป็น flag ที่ไม่มี daily flow; `is_tutorial` ใช้กับต้นแบบโรงเรียนสายน้ำที่เล่นในหน่วยความจำ ประวัติภาพในเซฟ v3 ปัจจุบันไม่ใช่ payload M5 ฉบับเสนอซึ่งต้องกำหนดรุ่นใหม่ก่อนพัฒนา

[ชุดออกแบบเล่นซ้ำ](design/REPLAYABILITY_PROPOSAL.md) มีการ์ด 30 IDs เหตุการณ์ 15 IDs ข้อตกลงใหม่ 6 แบบ และข้อเสนอความยาก 10 ระดับ ต้องแยกจากกฎปัจจุบัน; ไฟล์ `*.proposal.json` ไม่ถูก engine โหลด ความยากระดับ 6 ที่ลดจำนวนข้อเสนอการ์ดยังไม่มีผลต่อการเล่น

[แผนโรงเรียนสายน้ำครบ 6 บท](design/SCENARIO_CAMPAIGN.md) มีต้นแบบบท 01 และ 03 แล้วตามคู่มือข้างต้น บท 02 และ 04–06, checkpoint และสมุดตราถาวรยังไม่มี และยังไม่ตรวจโดยผู้เล่น; `SaveIO` ข้ามบันทึกและไม่รับโหลด tutorial state จึงไม่มี Continue บทเรียน

[กลไกตามฤดู](design/SEASONAL_MECHANICS.md) และ [เอฟเฟกต์ฉาก 12 รายการ](design/SCENE_EFFECTS.md) ทำค้ำบ้านหนึ่งเทิร์นและความชื้นสะสมในนาแล้วตามคู่มือข้างต้น ส่วนเศษวัสดุค้างประตูและจังหวะภาพ/เสียงที่เหลือยังเป็นแบบเสนอ ไม่มีใน runtime; ชุดเต็ม `seasonal_works_v1` ยังไม่เปิดใช้ ค่าต้นทุนและงบภาพในแบบยังไม่ผ่านการทดลองสมดุลหรือวัดประสิทธิภาพ

[โลกเกมลุ่มน้ำสายหวน](design/WORLD_OF_SAI_HUAN.md) เป็นแบบเสนอฉาก ผู้คน และเรื่องเล่า พร้อมภาพแนวคิด AI ชื่อถิ่น/ตัวละครและเส้นเรื่องใหม่ยังไม่อยู่ใน runtime; 4 ถิ่นไม่ใช่ 4 แผนที่ที่เปิดเล่น กระดาน 61 ช่องยังแทนชุมชนหนึ่งแห่ง ไม่มีการจำลองการแลกเปลี่ยนน้ำ การค้า หรือความสัมพันธ์ระหว่างหมู่บ้าน
