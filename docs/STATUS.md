อ่านหน้านี้ก่อนเริ่มงาน ใช้โค้ดและ [ค่ากฎจริง](../data/balance.json) ตัดสินพฤติกรรมที่มีอยู่ เอกสารนำเข้าเป็นข้อกำหนดต้นฉบับ ไม่ใช่รายการฟีเจอร์ที่ทำเสร็จแล้ว

| ผู้นำ | เลือกได้ครบ `farmer`, `carpenter`, `fisher`, `soil_doctor` ตั้งแต่เริ่ม ไม่มีระบบปลดล็อกข้ามรอบ |

| คำสั่ง | ขุด ถม ทำนา บ้าน บ้านยกพื้น เรือนแพ ประตู บึง ไซ ยุ้ง ตัดไม้ ปลูกป่า ระหัด รื้อถอน เปิด/ปิดประตู; เครื่องมือบางชนิดมีเงื่อนไข unlock |

| หน้าจอ | เมนู Continue, HUD ไอคอนทรัพยากร/เป้าหมายหลักที่เห็นเสมอ, แผงภัยเร่งด่วนพร้อมปุ่มดูจุดแก้ไข, inspector, สรุปปี/จบรอบ, ประวัติผลเทิร์น, sandbox น้ำแยกจากรอบเล่น |
| ภาพและค่าตั้ง | ถนนโค้ง/บันได คนเดินทำงาน/ขนของ น้ำตามทิศจริง ภาพอาคารตามอายุและความเป็นอยู่; หมู่บ้าน/พืช/แสงตามฤดู น้ำ/ฝน ผลคำสั่งและผลจริง; Reduce motion, ภาษา, คำเตือนแรงงาน ดู [หมู่บ้านมีชีวิต](features/LIVING_VILLAGE.md) |

ยังไม่ได้รับสเปก `03_hex_map.md` การสร้างที่ราบใช้ [สมมติฐานระหว่างรอสเปก 03](history/PROGRESS.md#สมมติฐานระหว่างรอสเปก-03) และ [MapGen ที่ใช้งานจริง](../core/map_gen.gd) อย่าใช้แบบเสนอหุบเขา/ปากแม่น้ำอธิบาย generator ปัจจุบัน

ผู้นำใช้ค่าจาก `balance.json`: farmer เพิ่มอาหารข้าวที่ให้ผลผลิต +1 ต่อช่องเมื่อเก็บเกี่ยว; carpenter ลดไม้บ้าน/บ้านยกพื้น/เรือนแพ 1; fisher เพิ่มอาหารไซต่อเทิร์น 1; soil_doctor ลดแรงงานขุด/ถมทั้งสองฤดู 1

เป้าหมายเสริมตรวจหลังเก็บเกี่ยว ต้องผ่านทุกเงื่อนไขในการเก็บเกี่ยว **ครั้งเดียวกัน** แล้วเก็บเหรียญถาวรในรอบนั้น:

| ID | เงื่อนไขพร้อมกัน |
|---|---|
| `none` | ไม่เลือกเป้าหมาย |
| `growth` | ประชากร ≥12 |
| `forest` | ประชากร ≥8 และป่าโตเต็มที่ ≥8 ช่อง |
| `rice` | ประชากร ≥8 และอาหารข้าวในการเก็บเกี่ยวครั้งนั้น ≥18 |

เหรียญให้คะแนนพื้นฐาน 50 เพียงครั้งเดียว การไม่สำเร็จเป้าหมายไม่ทำให้แพ้หรือขัดขวางการชนะ ดูรายละเอียด [รอบยาวและเป้าหมาย](features/LONG_RUNS.md)

## กฎที่ต้องรักษาเมื่อแก้ระบบ

- เทิร์น: จำลองน้ำ → ซับน้ำ → ระเหยเฉพาะฤดูแล้ง → ความเสียหาย → ผลผลิต; ศาลาถึงระดับน้ำ 2 แพ้ทันทีตามค่าเริ่มต้น
- เก็บเกี่ยว: รวมข้าว → กินอาหาร → คนย้ายเพราะหิว → คนย้ายเพราะบ้านไม่พอ → เกิด → อาหารเน่า → ตรวจผลรอบ/เป้าหมาย คนเหลือ 0 แพ้; รอดเก็บเกี่ยวปีสุดท้ายชนะ
- พรีวิวเทิร์นปัจจุบันใช้ resolver เดียวกับผลจริงบนสำเนา ต้องไม่เปลี่ยน state/RNG/ประวัติ/เซฟ; ไม่ใช่คำรับประกันฝนที่ยังไม่เปิดเผยของเทิร์นอนาคต
- คำสั่งและ resolve ไม่สุ่มเพิ่ม; forecast สุ่ม 4 draws ต่อปี เก็บ RNG ไว้กับ state
- Undo/Redo ใช้ snapshot เต็ม สูงสุด stack ละ 200; คำสั่งใหม่ล้าง Redo; จบเทิร์นล้างทั้งคู่; สำเนา/โหลดไม่มีประวัติเหล่านี้
- คะแนน = `(ประชากร×10 + อาหาร + โบนัส) × (1 + difficulty×0.1)` ปัดเป็นจำนวนเต็ม; เมื่อชนะได้เพิ่มบ้านไม่พัง 50 / ศาลาไม่เคยเปียก 30; เหรียญเป้าหมายเพิ่มก่อนตัวคูณ
- Modifier จริงเรียง default → map → run mode → leader → difficulty สะสม → year mods; ยังไม่รวมการ์ด

## เซฟและขอบเขตข้อมูล

- `GameSession` เป็นผู้ checkpoint หลังเปลี่ยนรอบจริง; `GameFlow` ไม่ทำ disk I/O
- เกมใหม่จากเมนู/boot มีประวัติภาพอาคาร ใช้ envelope **v3**; รอบ legacy classic + none ยังใช้ **v1**, long หรือมีเป้าหมายใช้ **v2**; internal state version ยังเป็น 1 ทุกแบบ
- `settlement_progress` มีสภาพส่วนรวม/ประวัติอาคาร ตรวจหลังเก็บเกี่ยวและพัฒนาภาพทีละระดับ ไม่เพิ่มทรัพยากร ความจุบ้านหรือความทนน้ำ โหลด v1/v2 ไม่สร้างอายุย้อนหลังหรือเขียนไฟล์ใหม่เอง
- เซฟรักษา float64/RNG แบบตรงค่า; validator ปฏิเสธฟิลด์การ์ด/ข้อเสนอ/เหตุการณ์ที่ไม่ว่าง เพราะยังไม่มีระบบรองรับ
- ประวัติผลเทิร์นเก็บเฉพาะ session สูงสุด 30/60 รายการ; โหลดเริ่มประวัติใหม่; Undo/Redo ไม่ลงเซฟ
- ภาษา/Reduce motion/คำเตือนแรงงานอยู่ใน settings แยกจาก checkpoint รอบเล่น ดู [สัญญาเซฟ](development/SAVE_IO.md)
- เส้นทาง คนเดิน กระแสน้ำรายขอบ และแผนที่อาหารข้าว/ปลาสำหรับภาพเป็นข้อมูลชั่วคราว ไม่ลงเซฟและไม่สุ่มเพิ่ม ถนนไม่เปลี่ยนสิทธิ์การผลิตของรอบเดิม

## ยังไม่มีในเกม

**M5 ยังเป็นแบบเสนอที่รออนุมัติ**: การเลือกการ์ด เหตุการณ์ ข้อตกลงรายปี profile/unlocks แผนที่ valley/estuary และ daily challenge ไม่มี flow เล่นจริง แม้ enum/fields/modifier บางส่วนเตรียมไว้แล้ว `is_daily`/`is_tutorial` เป็น flags ไม่ใช่ระบบที่เล่นได้ ประวัติภาพในเซฟ v3 ปัจจุบันไม่ใช่ payload M5 ฉบับเสนอซึ่งต้องกำหนดรุ่นใหม่ก่อนพัฒนา

[ชุดออกแบบเล่นซ้ำ](design/REPLAYABILITY_PROPOSAL.md) มีการ์ด 30 IDs เหตุการณ์ 15 IDs ข้อตกลงใหม่ 6 แบบ และข้อเสนอความยาก 10 ระดับ ต้องแยกจากกฎปัจจุบัน; ไฟล์ `*.proposal.json` ไม่ถูก engine โหลด ความยากระดับ 6 ที่ลดจำนวนข้อเสนอการ์ดยังไม่มีผลต่อการเล่น

## หลักฐานและงานที่ยังไม่ผ่าน

- ตรวจงานหมู่บ้านมีชีวิต 2026-10-18 บน Godot **4.6.3**: **328 Godot tests**, boot CLI **10 tests** (66 launches), Python balance checker **21 tests** และ balance CLI ผ่าน; ตรวจ native ไทย–อังกฤษ 1280×720 พร้อมเซฟ/input/ภาพ ดู [รายละเอียด](history/PROGRESS.md#2026-10-18--หมู่บ้านมีชีวิตและอ่านสถานการณ์จากภาพ) และ [CI](../.github/workflows/tests.yml) ผลนี้รับรองการทำงาน ไม่ใช่การยืนยันสมดุลทุกระดับหรือ playtest โดยผู้เล่น
- **M3 / TS-06 ยังไม่ผ่านครบ**: baseline ที่เก็บไว้ farmer d0 ชนะ 63.5% เทียบเป้า ≤5%; greedy d0 23.5% ผ่านช่วง 20–60% ดู [รายงานระบบหลักย้อนหลัง](history/M3_CORE.md#ผลสมดุล)
- ชุดอาหารทดลอง `h5_g3` ได้ farmer d0 0.5%, greedy d0 28%, greedy d10 46.5% และ d10 เกินเป้าเวลา จึง **ไม่ได้นำค่าชุดนี้มาใช้จริง** ดู [ผลทดลองที่ไม่ผ่าน](history/M3_BALANCE_FOLLOWUP.md)
- รอบยาวมี probe คำสั่งถูกกฎและตัวอย่างสำเร็จทุกเป้าหมาย แต่ชุดเล็กนี้ไม่ยืนยันสมดุลหรือความสนุก เป้าหมายบาง seed สำเร็จตั้งแต่ปี 1–2
- ตรวจ native mouse/keyboard ไทย–อังกฤษและ fixture หน้าจอแล้ว; ยังไม่มีหลักฐานปิดเกณฑ์ให้ผู้ใช้/เพื่อนเล่นจริงครบตาม [ROADMAP](ROADMAP.md) อย่าเทียบเทสต์อัตโนมัติกับการยืนยันโดยคน
