# การทดลองสมดุล M3 เพิ่มเติม

> รายงานคัดกรองย้อนหลัง ไม่ใช่ค่าที่นำไปใช้จริงหรือข้อสรุปสมดุลของรุ่นปัจจุบัน ดู [STATUS](../STATUS.md) และ [วิธีทำซ้ำการทดลอง](../development/BALANCE_EXPERIMENTS.md)

ตรวจเมื่อ 2026-10-16 ด้วย Godot 4.6.3 บนโค้ด `08120bd` รวม 83 ชุดค่า/บอท จำนวน 3,520 เกม ใช้ plains, farmer leader, difficulty 0, seed เริ่มที่ 1 และ greedy 8 ตัวเลือกตามเดิม ไม่มีการแก้สูตรคะแนนหรือ policy ของบอท

**ยังไม่พบชุดค่าที่ผ่านเป้า TS-06 ทั้งสองบอท** ไฟล์ balance เริ่มต้นจึงยังเหมือนเดิม ข้อมูลรวมและ override ที่ใช้ทุกแถวอยู่ใน [m3_balance_screen.csv](../reports/m3_balance_screen.csv) ข้อมูลนี้เป็นการคัดกรองด้วย seed ชุดต้นเดียวกัน หลายแถวมีเพียง 20–50 เกม ไม่ใช้แทน benchmark 200 เกมของ [M3_CORE](M3_CORE.md)

C3 ใช้ค่าเหล่านี้เฉพาะในหน่วยความจำของ process ทดลอง:

```json
{"paddy_labor":3,"food_per_person":3,"harvest_paddy_bonus":-2,"start_food":18,"year5_inflow_multiplier":2,"fish_trap_yield":3}
```

farmer ชนะ 3 แพ้ศาลา 42 และแพ้ประชากร 155 เกม; greedy ชนะ 5 แพ้ศาลา 14 และแพ้ประชากร 21 เกม อัตรา greedy จาก 40 เกมยังไม่ใช่การยืนยันสมดุล อีกทั้งโบนัสนา −2 เป็นการเปลี่ยนกติกาที่มีผลมาก: เมื่อรวมผู้นำ farmer +1 จะเหลือ −1 จึงไม่ควรเปลี่ยนค่าเริ่มต้นจากผลนี้

ทำซ้ำแต่ละแถวได้หลัง import โปรเจกต์ โดยกำหนดค่าใน SceneTree script ก่อนเริ่มเกม เช่น:

```gdscript
extends SceneTree

func _initialize() -> void:
    var overrides := {
        "paddy_labor": 3, "food_per_person": 3, "harvest_paddy_bonus": -2,
        "start_food": 18, "year5_inflow_multiplier": 2, "fish_trap_yield": 3,
    }
    DataDB.balance()["mods_default"].merge(overrides, true)
    for seed_value in range(1, 41):
        var result := BotGreedy.play_game(seed_value, "greedy")
        if not result["error"].is_empty():
            quit(1)
            return
        var state: GameState = result["state"]
        print(seed_value, ",", C.enum_name(C.Outcome, state.outcome), ",", state.year)
    quit()
```

รันด้วย `godot --headless --path . --script /absolute/path/to/probe.gd` ใช้ `mods`, `bot` และ `seed_end` ใน CSV เพื่อเปลี่ยนชุดทดสอบ ต้องเริ่ม process ใหม่ต่อชุดเพื่อไม่ให้ค่าทดลองปะปนกัน ข้อมูลเวลาเป็นเวลาบนเครื่องที่มีงานอื่นรันร่วม จึงใช้เทียบคร่าว ๆ เท่านั้น

แนวทางถัดไปคือหาความรุนแรงและจังหวะน้ำที่เปิดให้ป้องกันได้ พร้อมตรวจช่องทางผลิตอาหาร โดยคง policy ตามสเปกในการวัดผล ชุดค่าที่จะใช้จริงยังต้องทดสอบอย่างน้อย 200 เกมต่อบอท ตรวจ difficulty 10 และเวลา แล้วเสนอผลก่อน–หลังตามสเปกก่อนเปลี่ยนค่าเริ่มต้น
