# ความคืบหน้า

บันทึกย้อนหลังตามวัน ข้อความและจำนวนเทสต์แต่ละรายการสะท้อนเวลานั้น อ่าน [STATUS](../STATUS.md) สำหรับพฤติกรรมปัจจุบันและงานที่ยังค้าง

## 2026-10-18 — หมู่บ้านมีชีวิตและอ่านสถานการณ์จากภาพ

- เพิ่มเป้าหมายหลักที่มองเห็นเสมอ ไอคอนทรัพยากร/ผลผลิต และแผงภัยเร่งด่วนพร้อมปุ่มพาไปยังจุดเสี่ยง เครื่องมือ หรือพรีวิว ใช้ผลคำนวณเทิร์นปัจจุบันชุดเดิม รักษา inspector หลังเลือกจุดภัย และยังแสดงคำเตือนสำคัญเมื่อปิดภาพพรีวิว
- บันทึกกระแสน้ำตามขอบ hex และการสูบจริงเพื่อแสดงทิศตามแต่ละช่อง แยกผลจริงกับพรีวิวถัดไป ถนนสร้างจากกราฟทางเข้าและพื้นแห้ง ปัดมุม Bézier ตรวจความกว้าง/สิ่งกีดขวางและทำบันไดไม่เกินหนึ่งระดับ คนใช้เส้นเดียวกับถนน เดินไปนา ไซ ป่า และขนของตามคำสั่ง/ผลผลิตที่เกิดขึ้นจริง
- แยกชั้นถนน คน และกระแสน้ำออกจากพื้น bake; จำกัดคน 12 คน/คิว 24 งานและขอบน้ำเด่น 48 ขอบ ใช้หนึ่ง mesh สำหรับพรีวิวและ MultiMesh สูงสุดสองชุดสำหรับผลจริง หยุดเมื่อ Pause และใช้ภาพคงที่เมื่อ Reduce motion ไม่เพิ่มการผลิต ต้นทุน เวลาเดินทาง หรือ RNG
- เกมใหม่จากเมนู/boot ใช้เซฟ envelope v3 เก็บสภาพส่วนรวมและประวัติอาคาร ตรวจหลังเก็บเกี่ยว เปลี่ยนสภาพเมื่อได้เป้าหมายเดิมสองปีติดและพัฒนาภาพทีละระดับตามอายุ โหลด v1/v2 รักษาข้อมูลเดิม ไม่เติมอายุย้อนหลัง; ยังไม่มีเงิน/ทรัพย์สินรายบ้านและภาพไม่เพิ่มความจุหรือความทนน้ำ ข้อเสนอ payload M5 ต้องใช้รุ่นใหม่ในอนาคต
- Godot **4.6.3 ผ่าน 328 รายการ** (เพิ่ม 49 จากฐาน 279); boot CLI **10 รายการ / เปิด Godot 66 ครั้ง**, Python balance checker **21 รายการ** และ balance CLI ผ่าน รวม save validation/float64/RNG, preview, Undo/Redo, ทางถูกน้ำตัดและการไม่เปลี่ยน state จากภาพ
- ตรวจหน้าต่าง native 1280×720 ไทย **47/47** และอังกฤษ **47/47** รวม input คำสั่งถูกกฎ การบันทึก/โหลด/Undo/Redo โฟกัสจุดภัย และ Reduce motion [ผลตรวจไทย](../reports/living-village-qa-th.json) · [ผลตรวจอังกฤษ](../reports/living-village-qa-en.json) ภาพเริ่มเกมจริงและ controlled fixtures พร้อมคำอธิบายอยู่ใน [คู่มือฟีเจอร์](../features/LIVING_VILLAGE.md)
- ตัวอย่าง llvmpipe แบบหยุดชั้นภาพ เปรียบเทียบเปิด/ซ่อน 8 frames: ไทย 262/180 draw calls, อังกฤษ 256/174 (เพิ่ม 82); เวลาเฉลี่ยประมาณ 269/232 ms และ 285/237 ms ตามลำดับ เป็นข้อมูล software renderer ในเครื่องร่วม ไม่ใช่ GPU benchmark หรือเทียบกับ branch เก่า กราฟถนนตัวอย่าง 8 seeds ใช้ประมาณ 26–79 ms
- ต้นฉบับนำเข้าทั้ง 54 ไฟล์ยังตรง hash; ยังต้องตรวจโดยคนว่ามองภาพแล้วระบุภัยและสิ่งที่ควรทำได้ภายในประมาณห้าวินาที ผลอัตโนมัติและ fixtures ไม่ปิดเกณฑ์ human playtest หรือสมดุล M3 ที่ค้างอยู่

## 2026-10-18 — เลือกความยากและรักษาเทิร์นแรก

- เพิ่มตัวเลือกระดับ 0–10 ในเมนู พร้อมกฎสะสมและตัวคูณคะแนนไทย–อังกฤษจากค่าที่ใช้จริง คำอธิบายติดตามต้นทุนตามผู้นำ และบอกตรง ๆ ว่าระดับ 6 ใช้กฎการเล่นเหมือนระดับ 5
- เปิด `--difficulty=N` สำหรับเกมใหม่/ค่าเริ่มต้นเมนู ปฏิเสธค่าผิดก่อนเริ่มหน้าจอหรืออ่าน/เขียน checkpoint; HUD, Pause และผลจบรอบแสดงระดับใน state, Continue และเล่นอีกครั้งรักษาระดับเดิม
- แก้ seed เริ่มต้นที่เคย hash ข้อความ `42.0` ให้ได้เลข 42 และแก้ Enter จากช่อง seed ที่เคยไหลไปจบเทิร์นในหน้าจอใหม่ เทสต์ส่ง input ผ่าน Viewport จริงตรวจ state/เซฟเริ่มที่เทิร์น 1
- ตรวจ native mouse/keyboard ที่ 1280×720 ภาษาไทย–อังกฤษ: เลือกระดับ 6/10, ต้นทุนหลังเลือกช่างไม้, scroll/Tab ไป seed/เล่น, Enter เริ่มที่เทิร์น 1, Pause, Continue ระดับ 6 แม้ตั้งเมนูด้วย `--difficulty=10` และยกเลิกทับเซฟแล้ว bytes คงเดิม ภาพจากรอบ/เมนูจริงอยู่ใน [คู่มือความยาก](../features/DIFFICULTY.md); ผลจบและเล่นอีกครั้งตรวจด้วย controlled fixture แยกจากการชนะจริง
- Godot 4.6.3 ชุดเต็มผ่าน **279 รายการ** (เพิ่ม 9 จากฐาน 270); boot CLI ผ่าน **10 รายการ / เปิด Godot จริง 66 ครั้ง** และเพิ่มตรวจใน CI; Python balance checker 21 รายการกับ balance CLI ผ่าน ตัวตรวจเอกสารยืนยันต้นฉบับทั้ง 54 ไฟล์ยังตรง hash และลิงก์ที่ดูแลไม่มีปลายทางขาด
- ไม่เปลี่ยนค่า balance หรือ schema v1/v2 ไม่เปิดการ์ด/เหตุการณ์/กฎความยากฉบับเสนอ M5 เกณฑ์สมดุลและการตรวจโดยผู้เล่นยังเปิดอยู่

## 2026-10-18 — จัดเอกสารเพื่อพัฒนาต่อด้วย AI

- เพิ่ม AGENTS เป็นทางเข้าอ่าน และ STATUS เป็นหน้าสถานะปัจจุบัน แยกจากแบบเสนอและประวัติ พร้อมคู่มือคำสั่งพัฒนาและการส่งต่องาน

## 2026-10-18 — แบบเพิ่มความหลากหลายและโจทย์รายปี

- งานนี้เป็นเอกสารออกแบบและ catalog สำหรับทบทวนเท่านั้น ไม่มีการเปิดใช้ระบบ M5 หรือปรับค่าเกม ตัวเลขยังต้องตรวจสมดุลและความสนุกตามขั้นที่ระบุ
- ตรวจ catalog 30 IDs/ข้อความสองภาษา/modifier ตรงตาราง, เหตุการณ์ 15 IDs ตรงสเปก, ความยาก 10 ระดับ/ข้อตกลง 6 แบบ, ลิงก์เอกสาร และ hash ต้นฉบับ 54 ไฟล์ผ่าน พร้อมตรวจความสอดคล้องข้ามเอกสารแยกอิสระ

- ทดสอบตัวรันด้วย fixture ชั่วคราว: assertion ที่จงใจผิด, runtime error, parse error และ constructor error ทำให้ exit 1 โดยเทสต์ถัดไปยังรัน; filter ที่ไม่ตรงกับเทสต์ทำให้ exit 1
- import และเปิด main scene แบบ headless โดยไม่มี script error
- ตรวจภาพจริงด้วย OpenGL Compatibility บน virtual display: กระดาน น้ำ ภาษาไทย และแผงข้อมูลอ่านได้ รวมถึงหลังจำลองฝน 3 ครั้ง
- integration probe ตรวจคลิกขุด/ถม, ปุ่ม Space, reset เดิม, เปลี่ยน seed, การเลือก 61 ช่องด้วย ray และ view refresh ไม่เปลี่ยน state

### สมมติฐานระหว่างรอสเปก 03

ใช้เฉพาะที่ราบลุ่ม; ยังไม่อ้างว่าตรง H-02/H-03/MG-05 ฉบับเต็ม:

- axial pointy-top; ทิศเรียง `(1,0), (1,-1), (0,-1), (-1,0), (-1,1), (0,1)`
- index เรียง q ก่อน r; world x = √3(q + r/2), z = 1.5r; y = elevation × 0.4
- ต้นน้ำ `(0,-4)` ทะเล 5 ช่องที่ r = 4; แม่น้ำเดินลงทีละแถวด้วยทิศ 4 หรือ 5
- ศาลาอยู่ภายใน สูง 2 ระยะใกล้สุดจากแม่น้ำเท่ากับ 2 และมีบ้านติดกัน 3 หลังบนพื้นที่สูง ≥ 2
- ป่า 8–12 ช่องเลือกให้เกาะกลุ่มบนพื้นที่สูง ≥ 2
- ตรวจความปลอดภัยโดยจำลองฤดูแล้ง 3 เทิร์นและฝน 3 เทิร์น น้ำฝนรวมเป็นค่ากลางปีแรก แบ่งเท่ากัน; ถ้าศาลามีน้ำระดับ ≥ 1 จะลอง seed ย่อยถัดไป สูงสุดตาม config โดยคง seed หลักเดิม
- JSON ของ dictionary ที่ไม่กำหนดชนิด (`stats`, `year_mods`, `harvest_report`) แปลงตัวเลขที่ไม่มีเศษเป็น int ทั้งตอนเขียนและอ่าน เพื่อให้เทียบ dict หลัง JSON roundtrip ได้; scalar float ของ state/tile คงชนิด float
