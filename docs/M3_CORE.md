# ระบบกฎเกม M3

สถานะ: ระบบหลักและบอทใช้งานได้บน Godot 4.6.3 แผนที่ที่ราบลุ่ม ส่วนเกณฑ์สมดุลของบอททำนาอย่างเดียวยังไม่ผ่าน จึงยังไม่ถือว่า M3 ผ่านทุกเกณฑ์ก่อนขึ้น M4

## สิ่งที่เพิ่ม

- คำสั่ง 15 แบบตาม CM-10–CM-24: ตรวจ phase, unlock, ช่อง, ฤดู, เป้าหมาย, น้ำ, param, แรงงาน และไม้ตามลำดับ พร้อมต้นทุน/ผล/คืนไม้/valid_targets
- ฤดูแล้ง 3 เทิร์นและฝน 3 เทิร์นต่อปี ครบ 5 ปี; แรงงานเริ่มเทิร์นตามประชากรและ modifier
- น้ำ → ซับ/ระเหย → ความเสียหาย → ผลผลิตตามลำดับ T-08 รวมบ้านพัง นาตาย ไซดักปลา และนาปรังติดบึง
- เก็บเกี่ยว กิน ย้ายออกเพราะหิว/บ้านไม่พอ เกิด และอาหารเน่า ตาม T-13
- พยากรณ์จาก RNG ของเกม 4 draws ต่อปี; resolve/commands ไม่สุ่ม; คะแนนตอนจบรอบ
- Undo สูงสุด 200 คำสั่งเฉพาะในเทิร์น สำเนา/โหลด state ไม่คัดลอกประวัติ
- Preview บนสำเนา แสดงผล resolve โดยไม่เปลี่ยนต้นฉบับ ประวัติ หรือ RNG
- บอท farmer/greedy/random, CLI และ CSV รายรอบ

คำสั่ง waterwheel/raft_house มีเงื่อนไข unlock ตามสเปก แต่เกมหลัก M3 ยังไม่มีระบบเลือกการ์ดเพื่อปลดล็อก ค่าการปลดล็อกทดสอบผ่าน modifier fixtures

เพิ่ม [หน้าจอเกม M4](M4_PLAYABLE.md) ที่ใช้กฎ M3 แล้ว F5 เปิดเมนูหลัก มี HUD คำสั่ง พรีวิว สรุปปี และ Continue พร้อม [SaveIO ลงดิสก์](SAVE_IO.md) ส่วน sandbox M2 ยังเปิดแยกได้ การ์ด เหตุการณ์ โปรไฟล์และแผนที่อื่นเป็น M5

## API

```gdscript
var s := GameFlow.new_game({"seed": 42, "map_type": "plains", "leader": "farmer", "difficulty": 0})
var error := GameFlow.apply_command(s, Command.new("paddy", Vector2i(0, 0)))
# error == "" หมายถึงสำเร็จ; กรณีผิดเงื่อนไขคืน err.* และไม่เปลี่ยน state
s = GameFlow.undo(s)  # ต้องใช้ state ที่คืนมาแทนตัวเดิม
var prediction := GameFlow.preview(s)  # {state: GameState, report: TurnReport}
var report := GameFlow.end_turn(s)
if s.phase == C.Phase.HARVEST:
    GameFlow.continue_after_harvest(s)
```

new_game รับเฉพาะแผนที่ plains, leader ที่มีใน balance และ difficulty จำนวนเต็ม 0–10; config ผิดคืน null ไม่แอบเปลี่ยนเป็นแผนที่อื่น

ตาม T-10 พรีวิวหยุดหลัง resolve ก่อนเลื่อนเทิร์นหรือเก็บเกี่ยว ส่วน end_turn เลื่อนเวลา/เก็บเกี่ยวต่อ ดังนั้นเปรียบเทียบ report ทุกฟิลด์และผล terrain/water/crops ได้ตรงกัน แต่ phase, labor และผลเก็บเกี่ยวของ state หลัง end_turn อาจต่างจาก preview โดยตั้งใจ เมื่อเก็บเกี่ยวแล้วแพ้หรือชนะ จะรอ continue_after_harvest ก่อน GAME_OVER

base game ข้าม CARD_PICK/EVENT อย่างชัดเจนโดยไม่กิน RNG แทนขั้นที่ยังไม่มี การเพิ่มระบบ M5 ภายหลังจะเปลี่ยนลำดับ RNG รายปี จึงควรเทียบ seed ภายใน build เดียวกัน

## การตรวจ

ชุดทดสอบ 107 รายการ ครอบคลุมกรณีด้านล่าง; determinism ตรวจซ้ำด้วยจำนวนตัวเลือกบอทเริ่มต้นจริง

- ครบทั้งกรณีสำเร็จและเงื่อนไขปฏิเสธของทุกคำสั่ง พร้อมลำดับ error, rain costs, bounds, rounding, refunds, wheel direction และรักษา RNG
- ความเสียหายและผลผลิตใช้ระดับหลังซับ/ระเหย; นาปรังเลือกบึงน้ำมากสุดและ index ต่ำสุดเมื่อเท่ากัน; early hall loss ข้ามการผลิตแต่จบ damage pass
- เก็บเกี่ยว/คะแนน/prediction/undo มี fixture เฉพาะ; เกมสุ่ม 100 seed ตั้งแต่เริ่มจน GAME_OVER เปรียบเทียบพรีวิวที่เรียกซ้ำกับ report และผลจริงทุกเทิร์น
- greedy seed 42 รันสองครั้งได้ state สุดท้ายตรงกันทุกฟิลด์
- headless sandbox smoke ผ่าน; CI เพิ่ม bot CLI smoke ทุก policy

ตัวอย่างคะแนนใน TS-04 ที่เขียน 135×1.3=176 ไม่ตรงสูตร MT-01: ประชากร 10 อาหาร 5 ชนะโดยไม่เสียบ้าน/ศาลาไม่เปียก ที่ difficulty 3 ได้ `(100+5+50+30)×1.3` ปัดเป็น **241** ใช้สเปกเฉพาะคะแนน 09 ตามลำดับความสำคัญใน 00 และไม่แก้ไฟล์นำเข้าต้นฉบับ

## รันบอท

หลัง import โปรเจกต์:

```sh
godot --headless --path . --script res://tools/bot_sim.gd -- --bot=all --runs=20
# Benchmark แยกแต่ละ policy:
godot --headless --path . --script res://tools/bot_sim.gd -- --bot=farmer --runs=200 --seed-start=1
godot --headless --path . --script res://tools/bot_sim.gd -- --bot=greedy --runs=200 --seed-start=1
```

`--output=directory` เปลี่ยนที่เก็บ CSV; `--map=all` หมายถึงแผนที่ที่ใช้งานได้ตอนนี้คือ plains เท่านั้น ส่วน valley/estuary ถูกปฏิเสธด้วย exit 2 ข้อผิดพลาด/รอบที่เล่นไม่จบคืน exit 1

greedy ใช้สูตรคะแนน TS-05 เดิม แต่ลดจำนวนคำสั่งที่สุ่มประเมินจาก 40 เป็น 8 ตาม ROADMAP M3 ที่ให้ลดเมื่อช้า: probe seed 1 ที่ 40 ตัวเลือกใช้ 5.50 วินาทีต่อเกม ซึ่งไม่เหมาะกับเป้า 200 เกมในประมาณ 5 นาที ใช้ `--candidates=40` ได้เมื่อต้องการ จำนวนตัวเลือกเปลี่ยนการเลือกคำสั่งของบอทและผลชนะ จึงระบุจำนวนนี้ทุกครั้งที่รายงาน

## ผลสมดุล

ทุกชุดใช้ plains, farmer leader, difficulty 0, seed 1–200 เหมือนกัน ไม่มีการ์ด/เหตุการณ์; greedy 8 ตัวเลือก สูตรประเมิน TS-05 เดิม ข้อมูลรายรอบทั้งหมดอยู่ใน [m3_bots.csv](reports/m3_bots.csv)

| ค่า | บอท | ชนะ | ปีเฉลี่ยที่ถึง | แพ้ศาลา | แพ้ประชากร |
|---|---|---:|---:|---:|---:|
| ค่าเกมปัจจุบัน | farmer | 63.5% | 4.80 | 70 | 3 |
| ค่าเกมปัจจุบัน | greedy | 23.5% | 3.06 | 30 | 123 |
| ทดลอง: ฝน×2, ปี 5 เพิ่ม×3 | farmer | 4.0% | 3.54 | 182 | 10 |
| ทดลอง: ฝน×2, ปี 5 เพิ่ม×3 | greedy | 4.5% | 3.07 | 143 | 48 |

Baseline farmer ใช้ 15.62 วินาที และ greedy 192.61 วินาทีสำหรับ 200 เกม; ชุดค่าทดลองใช้ 14.51 และ 202.39 วินาทีตามลำดับ เวลาขึ้นกับเครื่องและงานที่รันร่วมกัน

เป้า TS-06 คือ farmer ชนะ ≤5% และไปถึงปีเฉลี่ย ≥3; greedy ชนะ 20–60% ค่าเกมปัจจุบันผ่านเกณฑ์ greedy แต่ farmer ชนะง่ายเกินไป ส่วนข้อเสนอเพิ่มฝนผ่านเกณฑ์ farmer แต่ทำให้ greedy ชนะเหลือ 4.5% จึง **ยังไม่แนะนำใช้ชุดค่าทดลองนี้เป็นค่าเริ่มต้น** ต้องจูนความรุนแรง/ช่วงเวลาน้ำและทดสอบทั้งสอง policy ต่อ

ชุดค่าทดลองเปลี่ยนเฉพาะ `mods_default.rain_inflow_multiplier = 2.0` และ `mods_default.year5_inflow_multiplier = 3.0` ในหน่วยความจำของ process ทดลอง ไฟล์ `data/balance.json` ยังคงสองค่านี้เป็น **1.0 / 1.0** ตามเดิม ไม่ได้นำค่าทดลองที่ยังไม่ผ่านทุกเกณฑ์ไปใช้กับเกม

เพื่อทำซ้ำค่าทดลองชั่วคราวก่อนเริ่มรอบ (ไม่ใช่ค่าเริ่มต้นใหม่):

```gdscript
DataDB.balance()["mods_default"]["rain_inflow_multiplier"] = 2.0
DataDB.balance()["mods_default"]["year5_inflow_multiplier"] = 3.0
var result := BotGreedy.play_game(1, "farmer")
```

สเปก 14 กำหนดให้เสนอผลก่อน/หลังและรออนุมัติก่อนเปลี่ยนค่าเริ่มต้นเมื่อเป้าสมดุลไม่ผ่าน รายงานนี้เก็บทั้งผลที่ผ่านและไม่ผ่านเพื่อใช้ตัดสินใจ ส่วนค่าทดลองนี้ยังไม่ควรอนุมัติเพราะไม่ผ่าน greedy target

M3 จึงพร้อมด้านกฎและความตรงของพรีวิว แต่ยังค้างการจูนสมดุล หน้าจอ M4 เพิ่มเพื่อให้ทดลองการเล่นจริงได้ โดยยังไม่ถือว่าเกณฑ์สมดุลครบ

ตรวจต่ออีก 83 ชุดค่า/บอท รวม 3,520 เกม ยังไม่พบค่าที่ผ่านทั้งสองเป้า ดู [ผลคัดกรองและค่าที่ใช้](BALANCE_SCREEN.md) การทดลองนี้คง policy และค่าเริ่มต้นเดิม

เพิ่ม [การทดลองอาหารและตัวตรวจเกณฑ์อัตโนมัติ](M3_BALANCE_FOLLOWUP.md): คัดกรอง 1,890 เกม และยืนยันอีก 600 เกม ชุดค่าที่ผ่าน d0 ยังไม่ผ่าน d10/เวลา จึงยังคงค่าเริ่มต้นเดิมและไม่ปิด TS-06
