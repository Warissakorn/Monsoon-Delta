# การบันทึกและโหลดรอบเล่น

เพิ่ม `core/save_io.gd` ตาม S-04 ของสเปก 02 และเชื่อมกับ `GameSession`, เมนู Continue และหน้าจอเกมแล้ว F5 เปิดเมนูหลัก ส่วนห้องทดลองน้ำเปิดแยกและไม่บันทึกทับรอบปกติ

## API

```gdscript
var error := SaveIO.save(state)  # user://save.json
if error.is_empty():
    var loaded := SaveIO.load_game()
    if loaded["state"] != null:
        state = loaded["state"]
```

ทุกเมธอดรับ path เป็น argument สุดท้ายเพื่อแยกเซฟทดสอบออกจากรอบเล่นจริง:

| เมธอด | ผลลัพธ์ |
|---|---|
| `save(state, path)` | `""` เมื่อสำเร็จ หรือ `msg.save_failed` |
| `load_game(path)` | `{state: GameState หรือ null, error: String}` |
| `has_save(path)` | ตรวจว่ามีไฟล์โดยไม่อ่าน แก้ หรือลบไฟล์ |
| `delete_save(path)` | `""` เมื่อสำเร็จ/ไม่มีไฟล์ หรือ `msg.save_failed` |

โหลด path ที่ไม่มีไฟล์คืน state เป็น null และ error ว่าง ไฟล์ที่อ่านได้แต่ผิดรูปแบบคืน `msg.save_corrupt` และพยายามลบตาม S-04 ส่วนความผิดพลาดในการเปิด/อ่านไฟล์คืน `msg.save_failed` โดยเก็บไฟล์ไว้ `has_save` จึงไม่ได้ยืนยันว่าโหลดได้ เมนู Continue ต้องตรวจผล `load_game` อีกครั้ง

การบันทึกเขียนไฟล์ `.tmp` ใน directory เดียวกัน ตรวจข้อผิดพลาด แล้ว rename ทับปลายทาง ถ้าเขียนหรือแทนที่ไม่สำเร็จจะคืน error และรักษาเซฟเดิมไว้ ไม่ลบเซฟเดิมก่อนเขียน เซฟบทสอนเล่นไม่เขียนทับหรือลบเซฟปกติ ส่วน GAME_OVER ลบเซฟตาม S-04

## ขอบเขตข้อมูล

รองรับรอบเล่นที่ราบลุ่ม ผู้นำที่มีใน balance, difficulty 0–10 และ phase PLANNING/HARVEST ที่ระบบ M3 ใช้งานจริง เซฟ HARVEST เก็บรายงานและผลแพ้/ชนะไว้ โหลดแล้วรอ `GameFlow.continue_after_harvest` ตามเดิม ไม่เรียกเก็บเกี่ยวหรือเริ่มปีซ้ำ การ์ด เหตุการณ์ และแผนที่อื่นยังไม่รองรับ

ตรวจชนิดและช่วงค่าก่อนเรียก `GameState.from_dict`: ฟิลด์ที่จำเป็น, enum, 61 ช่องตามลำดับ hex, ทรัพยากร, ฝน, พยากรณ์, รายงานเก็บเกี่ยว และ modifier ที่รู้จัก seed กับสถานะ RNG ใช้สตริงจำนวนเต็ม signed 64 บิต ไม่ผ่านตัวเลข JSON ประวัติ undo และ cache ไม่ถูกบันทึก; โหลดแล้วสร้าง index/mods ใหม่และเริ่ม undo ว่าง

จำกัดไฟล์ 1 MiB, ค่าจำนวนเต็มทั่วไปไม่เกิน `2^53−1` และ `water_iterations` ที่ได้หลังใช้ modifier ต้องเป็นจำนวนเต็ม 1–1000 เพื่อจำกัดงานจากไฟล์เซฟ ตรวจ UTF-8 ก่อนแปลงข้อความ เพื่อให้ไฟล์เสียคืน error ที่คาดไว้โดยไม่เกิด script error

รูปแบบหลักยังเป็น `{format: "monsoon_save", version: 1, state: {...}}` และเพิ่มข้อมูลบิต float64 ประกอบเพื่อรักษาค่าน้ำ ฝน พยากรณ์ และ modifier ให้ตรงเดิม Godot 4.6.3 อ่านตัวเลข JSON บางค่ากลับมาไม่ตรงบิต แม้เขียนด้วย `full_precision=true` เช่น `0.013960820753117553` จึงต้องเก็บความละเอียดเพิ่ม การอ่านบิตใช้ข้อมูลตัวเลขเท่านั้น ไม่ deserialize object จากไฟล์

ฟิลด์ `float64` ที่จำเป็นเก็บ `forecast_min`, `forecast_max`, `rain_inflows`, `tile_water` และ `year_mod_values` เป็นสตริง hex 16 ตัวต่อค่า (8 ไบต์จาก `encode_double`) ตรวจจำนวนรายการ ความเป็นค่าจำกัด และความสอดคล้องกับตัวเลข JSON ก่อนใช้บิตจริง ไม่รับเซฟที่ขาดข้อมูลประกอบนี้ ค่าต้นทุนต้องไม่ล้นขอบเขต `Vector2i` และ modifier ทางกายภาพที่มีผลทำให้น้ำหรืออาหารติดลบจะถูกปฏิเสธ

## การตรวจ

```sh
scripts/test.sh --filter=save
```

เทสต์ไฟล์ตรวจ roundtrip, เซฟเสีย/ชนิดผิด/UTF-8 ผิด, version ที่ไม่รองรับ, ช่วง seed/RNG, modifier, นโยบาย tutorial/GAME_OVER และกรณีเขียนล้มเหลวที่ต้องรักษาไฟล์เก่า เทสต์ต่อเนื่องอีกชุดเล่น 16 seed โดยบันทึกและโหลดทุกเทิร์นและทุก HARVEST แล้วเทียบค่าน้ำ รายงาน ผลเก็บเกี่ยว ปีถัดไป RNG ผลจบ และคะแนนกับเกมที่ไม่ได้โหลด

ผลบน Godot 4.6.3: เทสต์บันทึก–โหลด 18 รายการและชุดรวม 125 รายการผ่านทั้งหมด; import และ headless sandbox smoke ผ่าน

`GameSession` บันทึกหลังเริ่มเกม คำสั่งสำเร็จ undo จบเทิร์น และ continue หลังเก็บเกี่ยว ส่วน GameFlow ยังคงไม่มี I/O เพื่อให้บอท/preview/sandbox ไม่แตะเซฟปกติ หน้าจอเกมแสดงข้อความเมื่อเซฟล้มเหลวและให้ลองใหม่ก่อนกลับเมนูหรือปิดหน้าต่าง ดู [หน้าจอเกม M4](M4_PLAYABLE.md)
